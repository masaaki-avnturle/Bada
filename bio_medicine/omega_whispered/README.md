## 検査の構成

### 第一次検査 — 記号適性
数学論文に現れる方程式の記号（`∫ ∮ ∂ ∇ ⊗ ⊕ ⊢ ⊨ ⋆ ℵ 𝒪 𝔤 𝔭 ℏ ℘ …`）について、

| 設問種別 | 内容 |
|:--|:--|
| 記号の意味 | その記号が数学で何を表すか |
| 記号の分野 | どの専門分野で特徴的に使われるか |
| 文脈依存記号 | **同じ記号が分野で意味を変える**（例: `π` = 円周率 / 基本群 π₁ / 表現 π / 素数計数関数 π(x)） |

**PDF を読み込むと、その論文から実際に抽出された記号が優先的に出題されます。**

### 第二次検査 — 方程式の意味解析
方程式が **何を主張しているのか** を読み解きます。

| 設問種別 | 内容 |
|:--|:--|
| 方程式の意味 | 式が主張している内容（紛らわしい近傍の誤答つき） |
| 方程式の同定 | 式の名称 |
| **連想（簡単 → 専門）** | 簡単な方程式の構造が、専門分野でどう一般化されるか |
| 連想（専門 → 簡単） | 専門分野の方程式の原型にあたる基本式はどれか |

**連想検査**が本アプリの主眼です（第二次検査の約 4 割）。例:

| 簡単な方程式 | → | 専門分野の方程式 | 連想の中身 |
|:--|:-:|:--|:--|
| `a² + b² = c²` | → | `ds² = gᵢⱼ dxⁱ dxʲ` | 定数係数の計量を場所ごとに変えると曲がった空間の距離になる |
| `∫_a^b f′dx = f(b) − f(a)` | → | `∫_M dω = ∮_∂M ω` | 区間→多様体、端点→境界。ストークスの定理 |
| `∇×(∇φ) = 0` | → | `d ∘ d = 0` | 閉形式／完全形式の差＝de Rham コホモロジー |
| `∑ rⁿ = 1/(1−r)` | → | `ζ(s) = ∏_p (1 − p^−s)^−1` | 素数ごとの等比級数の積＝オイラー積 |
| `ab = ba` | → | `[x̂, p̂] = iℏ` | 可換性が壊れる度合い（交換子）そのものが物理量になる |
| `A𝐱 = 𝐛 の解の個数` | → | `ind(D) = ∫_M ch(E)Td(TM)` | rank-nullity を楕円型作用素へ持ち上げた指数定理 |

### 第三次検査 — 数学適性分野の診断

**どの専門分野に適性があるか**を、2 つの独立した測定を合成して診断します。

| 成分 | 測り方 |
|:--|:--|
| **志向**（思考スタイル） | 正誤のない設問 20 問（無限の扱い方 / 「同じ」とみなす基準 / 証明の好み / 対称性を見たとき何をするか / 挑みたい未解決問題 …）。各選択肢は分野への重みベクトルを持ち、**設問ごとの最大重みで正規化**（0〜1） |
| **実力**（分野別成績） | 第一次・第二次の設問を **難度 lv で重み付けした分野別正答率**（0〜1）。第一次/第二次の出題は分野が偏らないよう分野間で均した順に選ばれます |

```
総合 = 0.55 × 志向 + 0.45 × 実力      （両方測れた分野）
     = 志向 または 実力               （片方しか測れていない分野）
```

結果は 10 分野のランキングバー（総合／志向／実力を併記）と、**上位 3 分野のカード**として表示されます。
カードには「思考の型」「代表的な方程式」「代表的な記号」「隣接分野」「**次に学ぶとよい主題**」を提示します。

> 例（第一適性が微分幾何のとき）
> 思考の型: 座標に依らない量（テンソル・微分形式）で図形を記述し、局所の曲率から大域の形を導く
> 代表的な方程式: `ds² = gᵢⱼdxⁱdxʲ · ∫_M dω = ∮_∂M ω · ∫_M K dA = 2πχ(M)`
> 次に学ぶとよい主題: **多様体と微分形式 → 接続・曲率 → リーマン幾何**

**検査モード**は 4 つから選べます。

| モード | 内容 |
|:--|:--|
| フル | 第一次 → 第二次 → 第四次（瞬読）→ 第三次（適性分野診断） |
| 記号 + 方程式のみ | Ω 判定のみ |
| 数学適性分野の診断のみ | 思考スタイル設問だけを実施（Ω 判定は行わない） |
| 瞬読（フラッシュ）検査のみ | 瞬読設問だけを実施し、瞬読閾値を推定する |

**診断の妥当性検証**: ある分野への重みが最大の選択肢を常に選ぶ自動テストを 10 分野すべてで実行し、
**10/10 でその分野が第一適性**として返ることを確認しています（回答が結果に正しく反映されている、という検証）。

### 薬学のウィスパードテスト（薬物動態 / 薬力学 / 製剤 / 臨床）

出題系統を「薬学」にすると、四つの検査がそのまま薬学の内容になります。

| 検査 | 薬学での中身 |
|:--|:--|
| 記号適性 | `AUC · C_max · t½ · CL · V_d · F · k_e · EC50 · LD50 · TI · K_m · logP · pKa · TDM · MIC · p.o. · b.i.d.` の意味と分野 |
| 文脈依存記号 | `F`=バイオアベイラビリティ／自由エネルギー、`CL`=クリアランス／塩素ではない、`t½`=生物学的半減期／物理的半減期 |
| 関係式の意味 | `t½ = 0.693/k_e` · `V_d = D/C₀` · `C_ss = F·D/(τ·CL)` · `E = E_max·C/(EC50+C)` · `pH = pKa + log([A⁻]/[HA])` |
| **簡単な問題 → 関係する問題** | 下表（本検査の主眼） |
| 瞬読 | 用語（初回通過効果・肝初回通過・受容体拮抗・徐放性製剤…）と関係式のトークンをランダム提示 |
| 適性分野診断 | 8 分野のどこに適性があるかをプロファイル化 |

| 簡単な問題 | → | 関係する専門の問題 | つながり |
|:--|:-:|:--|:--|
| 薬は時間とともに体から消える | → | `C(t) = C₀ e^(−k_e t)` | 一定割合で減る＝一次消失。半減期が定義できる |
| 腎臓が悪いと薬が抜けにくい | → | `CLcr = (140−age)·wt / (72·S_cr)` | 腎機能から投与量を補正する（Cockcroft-Gault） |
| 飲み薬より注射のほうがよく効く | → | `F = AUC_po / AUC_iv × 100%` | 消化管吸収と肝初回通過で失われる分＝バイオアベイラビリティ |
| 薬を増やしてもある所から効かない | → | `E = E_max·C/(EC50+C)` | 受容体が飽和する（Emax モデル） |
| 酵素は基質が多いと頭打ちになる | → | `v = V_max·[S]/(K_m+[S])` | Michaelis-Menten。代謝の飽和＝非線形薬物動態の入口 |
| グレープフルーツと一緒に飲むな | → | CYP3A4 阻害 → AUC 上昇 | 代謝酵素の阻害で血中濃度が上がる相互作用 |

| 胃で溶けず腸で溶ける薬がある | → | `pH = pKa + log([A⁻]/[HA])` | イオン形／分子形の比が pH で決まり、吸収部位が変わる |

> **薬学の設問は教科書的な学習内容です。**
> 実際の診断・処方・服薬の判断には使用できません。服薬に関することは必ず医師・薬剤師にご相談ください。

| 簡単な問題 | → | 関係する専門の問題 | つながり |
|:--|:-:|:--|:--|
| 辞書は真ん中を開いて探す | → | `二分探索 = O(log n)` | 「半分にする」操作の回数が対数を生む |

| 一部だけ速くしても全体は速くならない | → | `S = 1/((1−p) + p/s)` | 並列化できない部分が上限を決める（アムダール） |

### PDF からの出題（化学・物理・薬学）

PDF を読み込むと、本文から **化学式**（元素記号として妥当なものだけを採用）と
**化学・物理・薬学の専門用語・記号表記**を検出し、`NaCl` `C9H8O4`（アスピリン）のように
既知の化合物が見つかれば「この論文に N 回出現した化学式は何か」という設問になります。

`UFO` `PIN` `P2P` のような頭字語を化学式と誤認しないよう、
**数字を含む・2 文字元素を含む・既知化合物のいずれか**で、かつ異なる元素が 2 種以上、という条件を課しています
（判定は 31 ケースのユニットテストで検証、リポジトリ内 120 本の PDF に対する誤検出は実質ゼロ）。

`CL` `TI` `MIC` `AUC` のような**英字だけの略号**も、`CLASS` `TIME` `atomic` の一部と
一致してしまわないよう**語境界**を課しています。`K_m` `E_g` `C_max` のような添字つき表記は、
PDF では `K m` のように分かれて出るため空白を無視して照合しつつ、
`union_int` の `n_i` のように長い識別子の途中と一致した場合は数えません。

### 第四次検査 — 瞬読（フラッシュ）

速読法の **瞬読** に倣い、**数学の専門用語・記号・バラバラに分解した方程式のトークン**を、
画面上の **ランダムな位置・角度・大きさで一瞬だけ一斉提示** し、消えた直後に問います。

```
注視点(+) 500ms  →  バースト提示（可変 ms・ランダム配置）  →  マスク 120ms  →  設問
```

マスク（ランダムな記号片）を挟むのは、**残像から読み取るのを防ぐ**ためです。

| 設問種別 | 内容 |
|:--|:--|
| 瞬読（専門用語） | 散らして提示された用語のうち、実際に表示されたのはどれか |
| 瞬読（用語→意味） | 表示された用語の **意味** はどれか（瞬読＋理解） |
| 瞬読（記号） | 表示された数学記号はどれか（PDF 読込時はその論文の記号を使用） |
| **瞬読（方程式バラバラ）** | 方程式をトークンに分解して散らし、**元の方程式はどれか** を当てる |
| 瞬読（個数把握） | 表示要素は全部でいくつだったか（逐次読みでなく面で捉える） |

例: `∇f = (∂f/∂x, ∂f/∂y, ∂f/∂z)` は `∇f` `=` `(∂f/∂x,` `∂f/∂y,` `∂f/∂z)` に分解され、
それぞれがランダムな位置・角度・文字サイズで散らして提示されます。

**露出時間は 2-down/1-up ステアケース法で適応制御**します（2 連続正答で ×0.78、1 誤答で ×1.32）。
反転点の幾何平均を **瞬読閾値**（約 70% 正答できる露出時間）として推定し、
スループット（要素/秒）・最短正答露出・段位（Class-S 〜 D）とともに表示します。

**検証**: 真の閾値を持つ模擬観測者でステアケースを 200 回シミュレートし、
真値 120/250/500 ms に対して推定値の中央値が 169/292/552 ms と単調に追随することを確認
（2-down/1-up は 50% 点ではなく約 70% 点に収束するため、真値よりやや長い側に出るのが理論通りの挙動です）。
実ブラウザでも、要求露出 600 ms に対し実測 626 ms（注視点・マスクの動作も含めて確認済み）。

問題銀行: **記号 114 種**（+ 文脈依存 9 種）· **方程式 51 式**（Lv1〜Lv5）· **連想対応 20 組** ·
**適性設問 20 問**（+ 10 分野プロファイル）· **専門用語 100 語**（10 分野 × 10 語）。
分野は 解析学 / 微分幾何 / 位相幾何 / 代数・数論 / 代数幾何 / 圏論・論理 / 確率・統計 /
作用素環・関数解析 / 表現論・群論 / 数理物理 の 10 分野。

## 何が「本物の処理」か — PDF 記号抽出器（`www/pdf_symbols.js`）

外部ライブラリを使わず、**PDF を実際にパースして数式記号を抽出**します。

- 通常オブジェクト + **圧縮オブジェクトストリーム**（`/Type /ObjStm`, PDF 1.5+）の展開
- `FlateDecode` の伸長（`DecompressionStream`、末尾ゴミのある壊れた流も部分復元）
- `/Type /Page` の `/Resources /Font` と `/Contents` を辿ったページ単位のテキスト抽出
  （`/Resources` は `/Parent` 継承にも対応）
- フォント別デコード
  1. **`/ToUnicode` CMap**（`bfchar` / `bfrange`）
  2. **`/Encoding /Differences`** のグリフ名 → Unicode（TeX/AGL の数学グリフ名）
  3. **CM/AMS フォントの内蔵エンコーディング**（CMMI・CMSY・CMEX・CMR・MSBM・EUFM）
     — `∂`(CMMI 0x40)、`ℵ`(CMSY 0x40)、黒板太字 `ℝ ℂ ℤ`(MSBM)、フラクトゥール `𝔤 𝔪`(EUFM) など
  4. `Type0`（Identity-H 等）の 2 バイトコード

抽出結果は、記号のヒストグラム・数式断片・埋め込みフォント一覧として表示され、
そのまま第一次検査の出題に使われます。

## 採点

正解した設問の難度 `lv` を、Γ カーネル由来の応答時間係数で重み付けします。

```
Γk(τ) = exp(−τ · log(1+τ)),  τ = 応答秒数 / 20
Ω     = 100 · Σ_correct lv·(0.7 + 0.3·Γk) / Σ_all lv
```

| Ω | クラス |
|--:|:--|
| ≥ 90 | Class-S — 完全共鳴 |
| ≥ 75 | Class-A — ウィスパード適性 高 |
| ≥ 60 | Class-B — 適性あり |
| ≥ 40 | Class-C — 訓練段階 |
| < 40 | Class-D — 共鳴未達 |

結果画面では、分野別正答率のレーダーチャート、到達難度、
**全設問の講評（誤答の解説つき）** を表示します。

#### Actions からダウンロードする

`bio_medicine/**` を更新して push すると、**ワークフローが自動で走り**、成果物が Actions に残ります。

1. [Actions →「Ω apps build」](https://github.com/masaaki-avnturle/Bada/actions/workflows/omega-apps-build.yml)を開く
2. 緑のチェックが付いた実行をクリック
3. **Summary** に成果物一覧と導入方法が表示される
4. ページ下部の **Artifacts** から `omega_whispered-android` / `-windows` / `-linux` / `-download` を取得

任意のタイミングでビルドしたいときは **Run workflow**（手動実行）を使います。入力は次の 3 つです。

| 入力 | 既定 | 内容 |
|:--|:--|:--|
| `apps` | `omega_whispered` | `all` にすると bio_medicine の 4 アプリすべてをビルド |
| `publish_release` | `false` | `true` にすると成果物を **Release** として公開（ログイン不要でDL可） |
| `release_tag` | `apps-v1.5.0` | 公開時のタグ名 |

- Artifacts の**ダウンロードには GitHub ログインが必要**で、ファイルは **ZIP に包まれて**届きます（保持 90 日）。
  ログイン不要・ZIP なしで配布したい場合は、手動実行で `publish_release` を有効にするか、
  タグ `apps-v*` を push してください（`omega-apps-release.yml` が全アプリをビルドして Release に添付します）。
- 実行ページの **Summary** には、Artifacts の一覧に加えて
  **Releases への直リンク**と `gh` コマンドの例が表示されます。

```bash
# gh CLI があるなら、実行 ID を指定してまとめて取得できる
gh run download <run-id> -R masaaki-avnturle/Bada

# 最新の実行から取得する
gh run download -R masaaki-avnturle/Bada -n omega_whispered-android
```

#### Ubuntu へのインストール

```bash
# .deb（/opt/Omega-Whispered にインストールし、デスクトップエントリとアイコンを登録）
sudo apt install ./Omega-Whispered-1.5.0-linux-amd64.deb
omega-whispered                    # またはアプリ一覧から起動
sudo apt remove omega-whispered    # アンインストール

# AppImage（インストール不要・単体実行）
chmod +x Omega-Whispered-1.5.0-linux-x86_64.AppImage
./Omega-Whispered-1.5.0-linux-x86_64.AppImage
# FUSE の無い環境では: ./Omega-…AppImage --appimage-extract-and-run
```

Ubuntu 22.04 / 24.04（x86_64）を想定。`.deb` の依存は
`libgtk-3-0, libnotify4, libnss3, libxss1, libxtst6, xdg-utils, libatspi2.0-0, libuuid1, libsecret-1-0`。

#### Android APK のインストール

#### ⚠ 旧版が入っていてインストールできないとき（署名不一致）

**症状**: 以前の版（数学のみの版など）が入っている端末に新しい APK を入れようとすると
「アプリがインストールされていません」「既存のパッケージと競合しています」となる。

**原因**: GitHub Actions のランナーには `~/.android/debug.keystore` が無いため、
Android Gradle Plugin が**ビルドのたびにランダムな署名鍵を生成**していました。
パッケージ名 `io.github.masaaki_avnturle.omega_whispered` は同じでも
**署名証明書が毎回違う**ため、Android が上書きインストールを拒否します。
加えて `android-versionCode` を指定していなかったため、内容を更新しても
毎回 `10000` が生成され、「同じバージョン」と見なされていました。

**対処（済み）**:

- リポジトリに**固定の署名鍵** `.github/keystore/omega-debug.keystore` を用意し、
  CI がこれを `~/.android/debug.keystore` として配置してからビルドするようにしました。
  以降のビルドはすべて同じ証明書（SHA-256 `fc3547e2…0d55`）で署名されます。
  CI はビルド後に `apksigner verify --print-certs` で実際の署名を照合し、
  一致しなければビルドを失敗させます。
- `android-versionCode` を明示（規則: `major*10000 + minor*100 + patch`）し、
  更新のたびに上げています（1.1.0 → `10100`、薬学を加えた 1.2.0 → `10200`、
  経済学・専門英語・露仏を加えた 1.3.0 → `10300`、情報科学を加えた 1.4.0 → `10400`、
  ドイツ語・中国語を加えた **1.5.0** → `10500`）。
  Windows / Linux 版もあわせて **1.5.0** です。

**お使いの端末での手順**: 旧版はランダムな鍵で署名されているため、
**一度だけ旧版をアンインストール**してから新しい APK を入れてください。

```bash
# 端末側: 設定 → アプリ → Omega-Whispered → アンインストール
# または adb が使えるなら
adb uninstall io.github.masaaki_avnturle.omega_whispered
adb install omega_whispered-debug.apk
```

**1.1.0 以降は、同じ鍵で署名されるのでアンインストール不要で上書き更新できます。**

Windows 版（NSIS）と Ubuntu 版（`.deb`）はもともと署名鍵の問題がなく、
バージョンが上がったので**そのまま上書きインストール／`apt install` で更新**できます。

| プラットフォーム | 旧版がある場合 |
|:--|:--|
| Android | 一度アンインストールが必要（1.1.0 以降は不要） |
| Windows 10/11 | インストーラを実行するだけで上書き更新 |
| Ubuntu (.deb) | `sudo apt install ./Omega-Whispered-1.5.0-linux-amd64.deb` で更新 |
| AppImage / 単一 HTML | ファイルを置き換えるだけ |

#### 自分でビルドする

```bash
cd bio_medicine/omega_whispered/electron && npm install
npm run dist:linux     # .deb + .AppImage（Linux 上で実行）
npm run dist:win       # Windows EXE（Windows 上で実行。Linux からは wine が必要）
```

APK は Android SDK + Cordova 12 が必要です（CI と同じ手順は
`../../.github/workflows/omega-apps-build.yml` の `android-apk` ジョブを参照）。

- 構成: `www/`（アプリ本体） · `download/`（配布物とダウンロードページ） ·
  `electron/`（EXE・deb・AppImage） · `cordova/config.xml`（APK） ·
  `build/icons/`（16〜512px のアイコン。APK でも使用） ·
  `build_single.js`（単一ファイル生成） · `../../.github/workflows/omega-apps-build.yml`（ビルド）。
