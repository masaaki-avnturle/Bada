📖 原理と使い方

1. 何をするアプリか

ゴーグル型コンピュータの HUD 風画面で任意の実写動画を再生し、 Web カメラに写った手の動きだけで時間軸を操作します。 動画はドラッグ＆ドロップ・ファイル選択・URL 貼り付けのいずれでも投入でき、 端末外には一切送信されません。マウス・タッチにも同じエンジンが割り当たっているので、 カメラが無い環境でも同じ操作感で使えます。

2. ジェスチャ仕様

  • かき分け (シャトル) — 画面中央が中立。手を左右へずらすと、変位に応じた速度で 巻き戻し / 早送り。速度は r = ±R·((|dx|−dz)/(span−dz))^γ の連続値で、 さらにスルーレート制限 |dr/dt| ≤ a を通すため、手がぶれても映像は滑らかに加減速します。
  • 高さ = 精度 — 手を上げるほど最大速度に近づき、下げるほど微速。 scale(y) = lo + (hi−lo)·(1−y)。コマ単位の追い込みは手を下げて行います。
  • フリック (跳躍) — 素早く払うと窓内ピーク速度に応じて clamp(k·v^1.3, 2s, 120s) 秒だけ一気に飛びます。
  • ホールド — 手を握ると即停止。手が画面外に出た場合も安全側で停止します。

3. なめらかさの仕組み (映像パイプライン)

<video> の currentTime を毎フレーム書き換える素朴なシーク駆動は、 圧縮動画では直前のキーフレームからの復号が間に合わず、巻き戻し・高速送りで必ずカクつきます。本アプリは:
  • フレームキャッシュ — requestVideoFrameCallback で復号済みフレームを ImageBitmap として捕捉し、再生ヘッドの前後 ±N 秒だけを保持する スライディングウィンドウに貯めます (範囲外は破棄して close())。
  • キャッシュ描画 — 巻き戻しと ×4 超の早送りはキャッシュから直接描くため、 デコーダのシーク待ちが再生に現れません。
  • 背景補填 — 未訪問区間では「同時 1 本」のシークキューが欠けたコマを取りに行き、 その間も最寄りのコマを表示し続けます (映像が止まらない)。
  • 中割りブレンド — キャッシュ間隔より細かい時刻では前後コマを α = (t−t_A)/(t_B−t_A) で重ね、擬似的にフレームレートを上げます。
  • モーションブラー — 高速域では直前の描画を薄く残し、コマ飛びを目で滑らかに繋ぎます。
  • 等速〜×4 — デコーダ本来の連続再生が最も滑らかなので、その領域では playbackRate による通常再生に自動で切り替えます (このとき音声も再生)。

4. ハンド認識パイプライン (すべて端末内)

  • 肌色抽出 — RGB を YCbCr に変換し 77 ≤ Cb ≤ 133、133 ≤ Cr ≤ 177、 かつ彩度のある画素のみ採用 (無彩色の壁・紙を除外)。
  • 動きエネルギー — 直前フレームとの差分が閾値未満の肌色は背景とみなし棄却。
  • 連結成分ラベリング — 4 近傍フラッドフィルで領域を数え、最大面積のブロブを手とする。 面積 → 距離代理、外接矩形に対する充填率 → 握り / 開き判定。
  • One Euro Filter — 速度適応カットオフ fc = fc_min + β·|ẋ| により、 静止時のふるえを消しつつ素早い払いには遅れない。

5. キーボード操作

Space 再生/停止、←→ コマ送り (Shift で 10 秒)、J/K/L、 Home/End、M 消音切替。ポインタモードでは Shift を押しながらのドラッグが「握り」です。

6. プライバシー

カメラ映像・動画ファイルはいずれも端末のメモリ内でのみ処理され、ネットワーク送信・保存は行いません。 アプリは外部 CDN も参照しない単一 HTML です (完全オフライン動作)。
