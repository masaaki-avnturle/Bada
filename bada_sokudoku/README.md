# Bada 瞬読 — 速読スタジオ

**対象者の本を、文字の固まりと(多行の)ブロックで速読させ、その本文が読み手にどう見えているかを画像として作り、まるごと録画するアプリケーション。**

頁の写真やスキャンを取り込むと、**画像処理トランスフォーマー**
(Swin 型の窓自己注意 + ずらし窓 + 注意ロールアウト) が版面を解析し、
**文字の固まり → 行 → ブロック → 読み順**を復元します。復元したブロックは、
対象者の視野幅と目標速度から決まる滞留時間で順に照らされ、視点は固まりから固まりへ渡っていきます。
そして画面に映すのは**読み手の姿ではありません**。映すのは
**「いま読み手には、この本文がどう見えているか」**の像です ── 中心窩の解像力の落ち方、
読み進む向きに非対称な知覚スパン、サッカード抑制、瞬きを、頁の画像に掛けたものです。
カメラは**視線を取るためだけ**に使い(同じ窓自己注意エンジンで顔と目を掴みます)、
その像は画面にも録画にも端末の外にも出ません。1 枚の `<canvas>` に合成されているので、
`captureStream()` + `MediaRecorder` で**「読み手に見えていたとおりの本文」が残る WebM 動画**を作れます。

依存ゼロ・単一 HTML・完全オフライン。ネットワークには一切出ません。カメラの像も測定値も端末の外へ出ません。

- 📄 アプリ本体: [`index.html`](index.html) (これ 1 枚で動きます)
- 🧪 エンジン単体テスト: `node bada_sokudoku/tools/engine-test.js` (219 項目)
- 🏗 ビルド: [`.github/workflows/sokudoku-app-build.yml`](../.github/workflows/sokudoku-app-build.yml)

## 文字を読まずに、読む所だけを解く

速読に必要なのは「どこからどこまでが一つの固まりか」「次はどこへ視点を送るか」であって、
その固まりが何という字であるかではありません。だから本アプリは**文字認識 (OCR) を経由せず**、
頁の画像の上で固まりと読み順だけを復元します。表示するのは**どこを見るか**だけです
(テキストを与えたときだけ、文字そのものを固まりで提示します)。

### 1. 前処理 — 照明を落とす

積分画像 (和と二乗和) を一度だけ作り、任意の窓の平均 μ と標準偏差 σ を O(1) で引けるようにしてから、
Sauvola の適応二値化で墨と紙を分けます。

```
T(x,y) = μ(x,y) · [ 1 + k · ( σ(x,y)/R − 1 ) ]     (k = 0.2, R = 0.5)
```

窓平均を基準にするので、本の写真につきものの照明の傾き (端が暗い / 中央が飛ぶ) を吸収します。

### 2. パッチ埋め込み — 画像を「語」に切る

P×P 画素のパッチごとに 12 次元の特徴 (墨密度・横/縦の勾配エネルギー・横/縦の遷移数・
平均ラン長・行方向と列方向の分散・原画の平均と分散・上下左右の非対称・バイアス) を取り、
**固定の直交射影**で d 次元に写して 2 次元正弦波の位置符号を足します。
重みは学習済みではなく決定論的な種から作るので、同じ頁は何度解析しても同じ版面に分かれます。

### 3. 窓自己注意 (Swin 型) — 二次爆発を避ける

頁 1 枚は数千パッチになり、全対全の注意 O(n²) は端末で回りません。画像トランスフォーマーの定石どおり
パッチ格子を W×W の窓に区切って窓の中だけで注意を取り、次の層で窓を半分ずらして境界を跨がせます。

```
Attn(Q,K,V) = softmax( QKᵀ/√d + B ) V ,   B(i,j) = −( α·|Δ行| + β·|Δ列| )
```

相対位置バイアス B は**等方ではありません**。横書きなら同じ行の隣を、縦書きなら同じ列の隣を
遠くまで見に行くよう α, β を入れ替えます — 文章は方向をもつ、という事実をそのまま注意の形にしたものです。
墨のない窓は辺を一本も生まないので、注意そのものを省きます (結果は変わらず、速度だけが上がります)。

### 4. 注意ロールアウト — 固まりを取り出す

層をまたいだ実効的な結びつきを、残差経路を勘定に入れたロールアウト (Abnar & Zuidema) で測ります。

```
Â⁽ˡ⁾ = 行正規化( ½(A⁽ˡ⁾ + I) ) ,   R = Â⁽ᴸ⁾ ⋯ Â⁽¹⁾
```

窓注意は同じ窓分割の層どうしなら区分対角行列なので、その積は窓の中で厳密に定義できます
(ずらした層は窓を跨ぐ辺として別に足します)。R が一様分布の τ 倍を超えたパッチ対を辺として
Union-Find で併合し、古典的な **RLSA (ラン長平滑)** の隣接と**論理和**を取ったものを
文字の固まりの連結成分とします。注意だけに賭けず古典と融合させるのは意図的です
(二段組のノドを跨いで繋がないことをテストで検査しています)。

### 5. 行・固まり・読み順

各ブロックを精査解像度の墨地図に戻し、投影プロファイルの谷で**行**に割り、
行に沿った空白 (中央値 + MAD で適応的に決めた閾値) で**文字の固まり**に割ります。
和文のように字間が一定で空白のない行は一塊になるので、そこは**字送り × 視野字数**で等分します。
読み順は **XY-cut**。縦書きと判定されたら列は右から左へ並べます。

書字方向の判定は、周期の鋭さではなく「**行間は字間より広い**」という組版の事実を使います
(和文は縦横とも字が格子に並ぶため、周期だけでは方向が決まりません)。
行に直交する方向のプロファイルにだけ、帯の太さに比して広い空きが現れます。

### 6. 滞留時間 — 対象者の側の式

```
t(u) = max( t_min , 60000 · chars(u) / cpm_eff )        cpm_eff = cpm · (1 + ramp·経過分)
視野負荷 = (1 ブロックの字数) / (対象者の視野幅)
```

目標 cpm から 1 ブロックの滞留を決め、句読点では少し延ばし、漸増率で
セッション中に速度を上げます。視野負荷は測定値ではなく設計上の指標で、1 を超えたぶんだけ
「一度に見切れていない」ことを示します。

### 7. 読み手の視線を取る(姿は映さない)

同じ窓自己注意エンジンを、こんどは**読んでいる人**に向けます。カメラのフレームを長辺 160 画素ほどに落とし、
パッチごとに 10 次元の特徴 ── **肌色密度**(YCbCr の色差規則。明るさ Y ではなく Cb,Cr で見るので
照明が変わっても閾値が動かない)・輝度の平均と分散・横縦の勾配・**前フレームとの差 (動き)**・暗さ・
上下の非対称・肌の中の影 ── を取り、頁のときの「墨密度」の代わりに**肌色密度**を密度として
同じ連結成分の抽出にかけます。いちばん大きな成分が**顔**、その上 18〜58% の帯の暗さの谷が**目**、
目の縦の広がりが**開き具合**(落ちた瞬間が**瞬き**)です。

```
視線指標 = clamp( 1.6 · (瞳の顔の中での偏り) + 0.8 · (頭の偏り) , −1, +1 )
前面カメラの像は左右が逆なので、読み進む向きに合わせて符号を反転する
```

この動きから**停留・サッカード・逆行**(読み進む向きと逆へ跳んだもの)**・瞬き・追従率**を数え、
`読んだ字数 ÷ 停留回数` で**測れた視野幅**を出して対象者プロファイルへ返せます。
**読み手の像は表示も録画もしません。**「読み手」タブに出るのは視線指標の折れ線と数だけです。

### 8. 読み手が見ている本文を、どう見ているかで描く

装置がどこを照らしているかは装置の都合です。読み手の側で起きているのは別のこと ──
**一度に受け取れるのは注視点のまわりだけで、離れるほど解像力が落ちる**(皮質拡大則)。
その範囲は読み進む向きに**非対称**(McConkie & Rayner の移動窓)で、横書きなら右へ広く左へ狭く、
縦書きなら下へ広く上へ狭い。さらに**跳んでいる最中は見えていない**(サッカード抑制)。

```
ぼけ(字) = max(0, (ecc − f₀) / E₂)      f₀ = 1 + 0.15·視野幅,  E₂ = 0.8·視野幅
ecc = √(a² + c²)
  a = (読み進む向きの距離/字送り) × (視野幅 / その向きの広がり)   ← 前は割安、後ろは割高
  c = max(0, |行をまたぐ距離|/行送り − 平地) × 9                  ← 平地 = 0.35 + (取れる行数−1)·0.5
```

頁はぼけの段ごとに作り置きし、**等離心率の楕円**(この式の逆写像)のやわらかいマスクで、
鮮明な段ほど内側に重ねます。周辺は暗くなるのではなく**頁の平均色に溶けます** ──
そこに字があることは分かるが字として見分けられない、という状態です。
視距離(倍率)は、知覚スパンが画面の約 22% を占める距離を既定にしています(本を持つ距離)。

**多行ブロック**(複数行を一度に見る面読み)にも同じ式が効きます。対象者の「一度に取れる行数」を
上げると平地が行方向に広がり、隣の行までぼけずに見えるようになります。逆に、1 行しか取れない読み手に
3 行のブロックを送っても**見えていない**ことがそのまま画像に出ます。

注視点の出どころは三つ: **装置が照らしている所**(カメラ不要)・**カメラの視線そのもの**・
**照らす所にカメラのずれを足したもの**。テキストを与えたときは、1 個ずつ流すのではなく
**実際に頁へ組版してから**視野をかけます ── 人が読んでいるのは頁だからです。

### 9. 録画

速読の描画も見え方の像もすべて 1 枚の canvas に合成されます。`canvas.captureStream(fps)` の MediaStream を
`MediaRecorder` に渡し、VP9 → VP8 → 既定の順に対応コーデックへ落として WebM を作ります。
録画されるのは合成後の画面そのもの — 見えたとおりが残ります。

## 使い方

1. **取り込み** — 頁の画像を選ぶ / その場で撮る、`.txt` を読む、`.tex` (提出した論文) を読む、
   内蔵サンプル、デモ頁の合成。ドラッグ&ドロップも可。
2. **版面解析** — 「この頁を解析」。重ね描きで **ブロック + 行 + 固まり / 固まりのみ /
   注意アフィニティ / 二値化 / パッチ密度** を切り替えて、何がどう解かれたかを確かめられます。
3. **速読** — 画面に映すもの(**読み手の見え方** / 装置の画面 / 並べて比較)、視距離、見え方の誇張、
   目標速度 (字/分)、1 ブロックの固まり数、**1 ブロックの行数(多行ブロック)**、最短滞留、漸増率、表示様式
   (スポットライト / 枠のみ / 固まりへ寄る / 瞬読フラッシュ)、単位 (ブロック / 固まり / 行) を決めて再生。
4. **読み手** — 「📷 カメラから視線を取る」(任意)。**姿は映りません**。出るのは視線指標の折れ線と、
   停留・逆行率・瞬き・追従率だけです。「🎯 測定値を対象者へ反映」でプロファイルに書き戻せます。
   カメラを使わない場合、注視点は装置が照らしている所になります。
5. **録画** — 「⏺ 録画開始」または速読タブの「⏺ 録画しながら再生」。停止すると動画一覧に並び、
   ⬇ リンクで保存できます。fps と解像度 (最大 1920×1080) は録画タブで選べます。
6. **対象者** — 現在の読速・視野幅・逆行率・目標倍率を入れて「この対象者に合わせて設定する」。
   セッション記録は JSON で書き出せます。

キーボード: `Space` 再生/停止 ・ `←` `→` 前後の固まり ・ `R` 録画。

白紙から固まりが出ないこと / 日本語チャンカが一字も落とさないこと / LaTeX 剥がし /
目標 cpm がそのまま実効速度になること / 最短滞留を割らないこと / 二分探索が総当たりと一致すること /

前面カメラで符号が反転すること・閉じた目の開き具合が瞬きの閾値をまたぐこと・顔のないフレームで落ちないこと・
前フレームとの差が動きとして出ること / 視線の追跡 (跳んだ回数・逆行の判定が横書きと縦書きで変わること・
瞬きの数え方・追従率・顔を見失ったフレームを跳びに数えないこと) /
**見え方**(視野幅の広い読み手ほど平地と E₂ が大きいこと・同じ距離でも後ろへ戻るほうが見えにくいこと・

**等離心率の楕円が離心率の式の厳密な逆写像であること**(中心までぼける不具合を捕まえる)・

**多行ブロック**(1 行指定なら従来と同じ結果になること・2 行ずつ束ねると帯 × 列に分かれること・

3 行取れる読み手には隣の行がぼけずに見えること) /
**組版**(字と単位が頁の内側に収まること・固まりが行をまたがないこと・縦書きの二列目が左に来ること・
頁に組んでも本文が一字も落ちないこと)。

## ネイティブ アプリ — Actions から落とす

**▶ [Bada Sokudoku app build の実行一覧](https://github.com/masaaki-avnturle/Bada/actions/workflows/sokudoku-app-build.yml)**
を開き、最新の実行 → ページ下部の **Artifacts**。

| アーティファクト | 中身 |
|:---|:---|
| `sokudoku-android-apk` | `bada-sokudoku-debug.apk` (Android) |
| `sokudoku-windows-exe` | `BadaSokudoku-*-x64.exe` (Windows 10 / 11 — NSIS インストーラ / ポータブル) |
| `sokudoku-linux-appimage-deb` | `BadaSokudoku-*-x86_64.AppImage` / `BadaSokudoku-*-amd64.deb` (Ubuntu / Linux) |

走らせ方は三つ:

1. **作業ブランチ (`claude/speed-reading-app-multiplatform-*`) へ push** → そのまま走り、Artifacts に並ぶ
   (`workflow_dispatch` のボタンは GitHub の仕様上、このファイルが既定ブランチ `main` に入ってからでないと出ないため)
2. `main` に入ったあと、**Actions タブの「Run workflow」**
3. **`sokudoku-v*` タグ**を押す → ビルドして GitHub Release に添付

APK は debug 署名なので、端末側で「提供元不明のアプリ」の許可が要ります。
AppImage は `chmod +x` してから実行、deb は `sudo apt install ./BadaSokudoku-*-amd64.deb`。

> 録画は `MediaRecorder` と `canvas.captureStream()` に依存します。古い Android WebView など
> これらを持たない環境では録画ボタンがその旨を表示し、静止画 (PNG) 書き出しに退避します。
>
> 読み手の捕捉は `getUserMedia` に依存します。Android では実行時のカメラ権限が要るので、
> APK は `CAMERA` を宣言し、`cordova-plugin-android-permissions` があればそれで求めます
> (端末の設定からこのアプリにカメラを許可してください)。Windows / Linux 版は Electron 側で
> `media` 権限だけを許可しています。カメラが開けないときはその旨を表示し、
> **速読と録画はカメラなしでそのまま使えます。**
