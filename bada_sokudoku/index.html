速読している「画像」を、画像のまま解く

    
文字を読むために文字を認識しなければならない、という前提を外します。速読で必要なのは
      「どこからどこまでが一つの固まりか」「次はどこへ視点を送るか」であって、
      その固まりが何という字であるかではありません。だから本アプリは文字認識(OCR)を経由せず、
      頁の画像そのものの上で固まりと読み順だけを復元し、その順に視点を送ります。


    
1. 前処理 — 照明を落とす

    
本の写真は必ず照明が傾いています。積分画像 (integral image) を 1 度だけ作り、
      任意の窓の平均 μ と標準偏差 σ を O(1) で引けるようにしてから、Sauvola の適応二値化

    
T(x,y) = μ(x,y) · [ 1 + k · ( σ(x,y)/R − 1 ) ]     (k = 0.2, R = 0.5)

    
で墨と紙を分けます。窓平均を基準にするので、頁の端が暗くても中央が飛んでも同じ結果になります。


    
2. パッチ埋め込み — 画像を語に切る

    
二値化した頁を P×P 画素のパッチに畳み、各パッチから 12 次元の特徴
      (墨密度・横/縦の勾配エネルギー・横/縦の遷移数・平均ラン長・行方向と列方向の分散・原画の平均と分散・バイアス)
      を取り、固定の直交射影で d 次元に写して 2 次元正弦波の位置符号を足します。これが画像側の「語」です。


    
3. 窓自己注意 (Swin 型) — 二次爆発を避ける

    
頁 1 枚は数千パッチになるので、全対全の注意 O(n²) は端末で回りません。
      画像トランスフォーマーの定石どおり、パッチ格子を W×W の窓に区切って窓の中だけで注意を取り、
      次の層で窓を半分ずらす (shifted window) ことで窓の境界を跨がせます。

    
Attn(Q,K,V) = softmax( QKᵀ/√d + B ) V ,  B(i,j) = −(α·|Δ行| + β·|Δ列|)

    
相対位置バイアス B は等方ではありません。横書きなら同じ行の隣を、縦書きなら同じ列の隣を
      遠くまで見に行くよう α,β を入れ替えます。文章は方向をもつ、という事実をそのまま注意の形にしたものです。


    
4. 注意ロールアウト — 固まりを取り出す

    
層をまたいだ実効的な結びつきは、各層の注意に残差分を混ぜて掛け合わせた
      ロールアウト (Abnar & Zuidema) で測ります。

    
Â⁽ˡ⁾ = ½(A⁽ˡ⁾ + I) を行正規化 ,  R = Â⁽ᴸ⁾ ⋯ Â⁽¹⁾

    
窓注意は同じ窓分割の層どうしなら区分対角行列なので、その積も同じ窓の中で厳密に定義できます
      (ずらした層は窓を跨ぐ辺として別に足します)。R が閾値 τ/n を超えたパッチ対を辺として
      Union-Find で併合し、古典的な RLSA (ラン長平滑) の隣接と論理和を取ったものを
      文字の固まりの連結成分とします。注意だけに賭けず、古典と融合させるのは意図的です。


    
5. 行と読み順

    
得られた各ブロックを原寸の墨地図に戻し、投影プロファイルの谷で行に割り、
      行に沿った空白 (中央値 + MAD で適応的に決めた閾値) で文字の固まりに割ります。
      読み順は XY-cut。縦書きと判定されたら列は右から左へ、行内は上から下へ並べます。


    
6. 滞留時間 — 対象者の側の式

    
t(u) = max( t_min , 60000 · chars(u) / cpm ) · (1 + 句読点加算) / ramp(τ)

    
目標 cpm から 1 ブロックの滞留を決め、句読点では少し延ばし、漸増率を掛けて
      セッション中に速度を上げていきます。視野負荷指数は

    
負荷 = (1 ブロックの字数) / (対象者の視野幅)

    
で、1 を超えたぶんだけ「一度に見切れていない」ことを示します。これは測定値ではなく設計上の指標です。


    
7. 録画

    
速読の描画はすべて 1 枚の canvas に合成されます。canvas.captureStream(fps) の
      MediaStream を MediaRecorder に渡し、VP9 → VP8 → 既定の順に対応コーデックへ落として
      WebM を作ります。録画されるのは合成後の画面そのものなので、見えたとおりが残ります。


    
継承したもの

    
sokudoku/ の瞬読トレーナー (C) から、10 行一瞬表示と語中シャッフル
      (語の内側だけを混ぜても読めるという耐性訓練) を引き継ぎ、表示様式「瞬読フラッシュ」と
      チェックボックス「語中シャッフル」として載せました。
      sokudoku/reports/ の論文 (.tex) は、前文と命令を剥がして本文だけを取り出す
      読み込み口を用意してあり、提出してきた論文そのものを教材にできます。

    
本アプリは文字認識を行いません。したがって「何と書いてあるか」は表示しません。
      表示するのはどこを見るかだけです。テキストを与えた場合のみ、文字そのものを固まりで提示します。
