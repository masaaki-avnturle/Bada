# Omega UltraNet — 同意ベースの暗号化コラボレーション

ネットワーク上の相手（IPアドレス指定）と、**相手の許可を得たうえで**接続し、
以前作成した結び目理論ベースの「量子暗号」（Jones / Kauffman 多項式から鍵を導出）
で暗号化しながら**共同作業**するためのシステムです。

HHKB キーボードアプリの「入力」を、ネットワーク越しに**共有入力面（共有バッファ）**
として複数人で扱えるようにした、その姉妹システムという位置づけです。

---

## ⚠ このツールが「やること / やらないこと」

**やること（合意に基づく共同作業）**
- エンドツーエンド暗号化されたグループチャット
- 共有コラボレーション・バッファ（共同編集用のテキスト面 = HHKB 共有入力面）
- サンドボックス化されたファイル交換（`workspace/received/` 限定）

**意図的にやらないこと**
- **遠隔コマンド実行・相手OSの操作は一切行いません**（バックドア／RAT ではありません）。
  ここでの「相手のマシンに入る」とは、**相手が承認した共有ワークスペースに参加する**
  ことを意味します。相手のOSを乗っ取る機能はありません。

### 2重の同意ゲート

| ゲート | 内容 |
|:--|:--|
| **暗号的同意** | 接続には、ホストが事前に**安全な経路で手渡した同じ結び目図(knot鍵)**が必要。持っていなければ相互認証に失敗し、ソケットは即切断されます。 |
| **人間による同意** | ホストは接続元IPと鍵フィンガープリントを画面で確認し、毎回手動で承認します（または `--allow` で許可IPを事前登録）。判断はすべて `workspace/connection_log.txt` に監査記録されます。 |

> つまり「勝手に他人のマシンへ入る」ことは構造上できません。
> 相手が鍵を共有し、かつ接続を承認したときだけ共同作業が始まります。

## 構成

| ファイル | 役割 |
|:--|:--|
| `omega_qkd.py` | 結び目図 → 32バイト鍵（`omega_jones_crypto_pkg` の C 実装を忠実に Python 移植、鍵はバイト単位で一致）＋ HKDF ＋ フィンガープリント |
| `secure_channel.py` | TCP 上の認証付き暗号チャネル（ノンス交換 → HKDF セッション鍵 → 相互認証 → encrypt-then-MAC、リプレイ防止カウンタ付き） |
| `omeganet.py` | 本体。`host`（ハブ＋同意ゲート）/ `join`（参加）/ `selftest` |
| `keys/shared_trefoil.knot` | 共有鍵となる結び目図のサンプル（= 共有シークレット） |
| `allowlist.txt` | 任意のIP許可リスト（テンプレート） |

依存ライブラリ無し。Python 3.8+ 標準ライブラリのみ。

---

## 暗号方式

1. **マスター鍵**：結び目図の Kauffman 括弧を 5 つの A 値で評価 → IEEE754 を連結 →
   SHA-256 で 32 バイト鍵。`omega_jones_crypto_pkg` の鍵と一致します。
2. **セッション鍵**：両者が 16 バイトの乱数ノンスを交換し、
   `HKDF-SHA256(master, salt = client_nonce‖server_nonce)` から方向別に
   4 鍵（送受信 × 暗号/MAC）を導出。セッションごとに新しい鍵になります。
3. **相互認証**：双方がトランスクリプト上の HMAC で鍵の所持を証明。
   鍵が違えば認証失敗 → 切断（＝暗号的同意ゲート）。
4. **レコード**：encrypt-then-MAC。鍵ストリームは HMAC-SHA256 のカウンタモード、
   完全性は HMAC-SHA256。方向別の単調増加カウンタでリプレイ／順序入替を拒否。

> 元の C 版はファイル暗号（AES-256-GCM）、本システムはその**ネットワーク版**で、
> 同じ結び目鍵・認証付き暗号・セッションごとの鍵更新を採用しています。

## 使い方

### 1. 共有鍵（結び目図）を相手に安全に渡す
`keys/shared_trefoil.knot` を信頼できる経路で共有し、両者でフィンガープリントを照合：

```bash
python3 omega_qkd.py keys/shared_trefoil.knot
# -> fingerprint: 5DDA-CC80-790E-7E0A   （両者で一致を確認）
```

### 2. ホスト（ワークスペースを共有する側）

```bash
python3 omeganet.py host \
    --key keys/shared_trefoil.knot --name alice \
    --workspace workspace --port 8765
    # 任意: --allow allowlist.txt で特定IPを自動承認
```
接続要求が来ると IP とフィンガープリントが表示され、`approve? [y/N]` で承認します。

### 3. 参加（許可を得て接続する側）

```bash
python3 omeganet.py join \
    --key keys/shared_trefoil.knot --name bob \
    --workspace workspace_bob --host 203.0.113.7 --port 8765
```

### 対話コマンド（ホスト・参加者共通）

| 入力 | 動作 |
|:--|:--|
| `<テキスト>` | 全員にチャット送信 |
| `/note <テキスト>` | 共有バッファに 1 行追記（共同編集） |
| `/send <パス>` | ファイルを相手の `workspace/received/` へ送信（最大 5 MiB、basename のみ） |
| `/who` | 参加者一覧 |
| `/help` | ヘルプ |
| `/quit` | 退出 |

## 動作確認

```bash
# ネットワーク不要・暗号/ハンドシェイク/リプレイ防止/認証ゲートの検証
python3 omeganet.py selftest
#   [PASS] handshake with matching key
#   [PASS] encrypted round-trip
#   [PASS] replay/out-of-order rejected
#   [PASS] wrong key blocked by auth gate
```

loopback での host ↔ join 実通信、チャット・共有バッファ同期・ファイル受信・
監査ログ生成も確認済みです。

## 注意

- このツールは **当事者全員の同意がある共同作業** を前提とします。
  許可なく他者のシステムへアクセスする目的では使用しないでください。
- 公開ネットワークで使う場合は、ホストのポートをファイアウォールで保護し、
  `--allow` か手動承認で接続元を必ず限定してください。
- 結び目図ファイル（共有鍵）は厳重に管理してください。漏れれば誰でも認証を通過します。
