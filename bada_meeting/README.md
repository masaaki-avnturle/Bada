# Bada 思念会議 (BadaMeeting) — コンピュータ同士が会議するアプリ

コンピュータ同士がテキストのパケットをやり取りし、**企画・プランナー・アプリケーションエンジニア**の 3 役が会議形式で「何を作るか・どれだけかかるか・いつまでに作るか」を話し合って決めます。人は**ポインタを使わずに** — キーボードと、キー 1 つの長短で打つ**電鍵 (モールス符号)** で — 複数行の発言を書いて会議に加われます。端末どうしは、**Bada Telegraph の音響電信** (音で送ってマイクで聞く) でやり取りできます。Android / Windows 10・11 / Ubuntu / ブラウザで動き、依存なし・単一 HTML・サーバーなしです。

> **できないこと**
> - **思考を読み取る装置ではありません。** 入力はキーボードと電鍵 (キーの長短) です。v1.0 にあった「ポインタを留めて選ぶ」入力 (Ω-Telepathy 方式) は v1.1 で取り除きました。
> - **言語モデルは入っていません。** 3 役は、分野ごとの知識表と決まった計算式で発言を組み立てます。知識表にあるのは 7 分野 (メッセージング・販売・予約・学習・健康記録・業務管理・ゲーム) と一般用の 1 つです。
> - 見積りと日程は目安です。実際の計画では担当者による確認が必要です。

## 会議の流れ

議題 (例: `スマホ向けの予約アプリを 3 か月で作りたい`) を送ると、各役割が議事録を読んで順に発言します。

| 役割 | すること |
|:--|:--|
| **企画** | 分野・対象・提供する価値・成功の指標・機能 (優先度つき) を提案。期限を超えたら、優先度の低い機能から次期に回す。最重要の機能は削らず、期限の延長を提案する |
| **アプリケーションエンジニア** | 構成 (クライアント・サーバー・保存)・主なデータ・機能ごとの工数を出し、対応環境の数と工程 (要件定義・設計・試験・公開準備) を上乗せして見積もる |
| **プランナー** | 見積りと期限を比べる。超えていれば企画に差し戻し、収まれば工程ごとの日程とリスク対策を組み、全員の合意を確かめて決定事項をまとめる |

例: `議題 → 提案 → 見積り (13.5 週間) → 懸念 (期限 13 週間を 0.5 週間超過) → 修正 (口コミを次期へ) → 再見積り (11.9 週間) → 日程 → 合意 → 合意 → 決定`

会議の途中で人が `期限を 12 週間にしましょう` と発言すると、議題を更新して話し合い直します。「議事録を保存」で、企画・設計と見積り・日程・リスク・発言の記録をまとめた Markdown を書き出します。

## 入力 — 複数行・ポインタなし

発言欄は複数行です。すべての操作にキーが割り当ててあり、マウスやタッチは要りません。

| キー | 動作 |
|:--|:--|
| `Enter` | 改行 |
| `Ctrl+Enter` | 発言する (会議が始まっていなければ議題として送る) |
| `Ctrl+Shift+Enter` | 新しい議題として送る |
| `Alt+1` 〜 `Alt+8` | 予測した候補を入れる (定型句と、議事録に出てきた語句。最後の行の末尾から予測) |
| `Alt+0` | 「役割が自動で発言」を外しているとき、その役割の案を発言欄に入れる |
| `F2` | 電鍵モードの入 / 切 |
| `F3` | 和文 / 欧文の切り替え |
| `F4` | 音響電信の開始 / 停止 |
| `F6` | 議事録を保存 |

**電鍵 (モールス符号)**: 電鍵モードでは、発言欄で `Space` を短く押すと「・」、長く押すと「－」になります。少し間を空けると 1 文字が確定します。欧文の符号表は Bada Telegraph と同じで、和文モールス (濁点・半濁点は直前のかなに付く) にも対応します。`Enter` で改行できるので、電鍵だけでも複数行を書けます。1 単位の長さは 60〜300 ms で調整できます。和文モールスに小書きの字 (ゃ・っ など) は無いので、大きい字で入ります。

タッチ端末用に、押している長さで打てる「電鍵」ボタンも置いてあります (キーボードが無い端末のためのもので、キーボードがあれば使う必要はありません)。

## コンピュータ同士のやり取り (サーバーなし)

経路は 2 つあります。

### 音響電信 (Bada Telegraph) — 接続の手続きなし

`F4` を押すと、発言を **FSK 変調音**にしてスピーカーから鳴らし、ほかの端末がマイクで聞いて復調します。同じ部屋に置くか、通話 (スピーカーホン) 越しに使います。接続コードのやり取りは要りません。

- 変調方式とフレームは Bada Telegraph (`bada_telegraph`、ブランチ `claude/touch-sensitivity-app-packaging-ep1xmm`) と同じです: space 1000 Hz / mark 1600 Hz・100 baud、フレーム = プリアンブル + SOF `0x7E` + 長さ + 本体 + チェックサム。元の実装に対し、流しながらの復調、チェックサムの照合、雑音を信号と見なさない判定を加えています。
- 100 baud は遅い (毎秒 10 バイト) ので、**役割の発言は本文を送りません**。全端末が同じエージェントを持っているので、「誰が・何番目に・どの種類の発言をしたか」と発言文の SHA-256 の先頭 4 バイトだけを 15 バイトのパケットで送り (約 2 秒)、受け取った側が自分のエージェントで同じ発言を作ってハッシュを照合します。
- 議題と人の発言は UTF-8 の文章として送ります。複数行もそのまま届き、長い文章は部分に分けて送ります (日本語 60 文字で約 20 秒かかります)。
- 聞き逃しへの備え: 次の発言が聞こえなければ送り直します。先の番号の発言が聞こえた端末は、足りない番号を要求し、その発言をした端末が送り直します。
- 自分が送信している間は聞きません。ほかの端末が鳴らしている間は送信を待ちます。

### 接続コード (WebRTC)

速くて確実な経路です。主催者が招待コードを作る → 参加者が貼り付けて返信コードを作る → 主催者が貼り付ける、の手順でつなぎます (すべてキーボードで操作できます)。発言は SHA-256 つきの JSON パケットで送られ、主催者が通し番号を付けて全員に配ります。**STUN サーバーを使わないので、接続できるのは同じ LAN の中です。**

どちらの経路でも、各端末に役割を 1 つ割り当てると、その端末のエージェントが自分の番に自動で発言します。「全役を 1 台で」を選べば 1 台だけでも会議が進みます。

## レポートのエントロピー方程式群の使い方

レポート *Entropy on manifold and differential of equation* (`system_transport.pdf`) に繰り返し現れる式を、発言の統計量に対応させています (`bada_claude/src/semantic.bada` と同じ対応)。

| 式 | 対応させた量 | 使い道 |
|:--|:--|:--|
| (E1) `x log x` | `S(p) = −Σ p log p` | 発言の情報量 H、議題とのずれ D (Jensen–Shannon) |
| (E2) `log(x log x) ≥ 2 (y log y)^{1/2}` | `x = e^H`、`y = e^D` | **門**: 通らない発言に「議題から外れている可能性」の印を付け、会議の文脈に加えない |
| (E3) `∫∫ 1/(x log x)² dx` | 候補の順位 r の事前分布 | 入力候補の確率 |
| (E4) 勾配二乗の汎関数 F | 発言ごとのずれ D の変化 | 会議の流れ (話題の飛びの少なさ) |

レポートは物理・幾何の文脈でこれらの式を述べており、会議や言語については定めていません。**どの量を x, y, f とみなすかは本アプリの設計上の選択**で、レポートから導かれた定理ではありません。計測は語の分布の統計であり、発言の内容が正しいかどうかは判定しません。

## 🧪 テスト

```sh
node bada_meeting/tools/test.js        # 単体テスト 62 件 (Node だけで動く)
node bada_meeting/tools/e2e-test.js    # 実ブラウザ 18 件 (Playwright + Chromium が必要。CI では実行しない)
node bada_meeting/tools/build.js       # src/ → index.html
```

- `test.js` は、モデムの変調 → 雑音 → 復調、電鍵の打鍵、そして 3 端末を実際のモデムでつないだ模擬の音響空間での会議 (送信が失われる場合を含む) を確かめます。
- `e2e-test.js` は、**すべての操作をキーボードだけで**行います。3 つの画面を WebRTC でつないだ会議のほか、別の端末が鳴らすはずの音を WAV にして偽のマイク入力として聞かせ、画面が復調して会議に応じることを確かめます。

**確かめていないこと**: 実際のスピーカーとマイクを通した端末間の音響通信 (部屋の反響、端末の音質、音量による影響)。Android では、マイクの権限をアプリの設定画面で許可する必要があるかもしれません (権限の宣言は入れてありますが、実機では未確認です)。マイクが使えない場合は送信のみになります。

## 📁 構成

```
bada_meeting/
├── index.html          # アプリ本体 (build.js の出力)
├── src/entropy.js      # エントロピー方程式群 (E1〜E4)
├── src/agents.js       # 3 役の能力: 分野の知識表・見積り・発言の組み立て
├── src/meeting.js      # 議事録・計測・役割の順番・計画書の書き出し
├── src/thought.js      # ポインタを使わない入力: 電鍵 (モールス符号) と候補の予測
├── src/telegraph.js    # Bada Telegraph の FSK モデムと、会議用の小さなパケット
├── src/acoustic.js     # 音響電信での送受信の規則 (送り直し・要求) と、スピーカー / マイク
├── src/net.js          # JSON パケットと WebRTC (接続コード方式)
├── src/ui.html         # 画面
├── tools/              # build.js / test.js / e2e-test.js
└── app/                # cordova (APK) / electron (EXE・AppImage・deb)
```

SHA-256 は [`bada_gpt/src/engine.js`](../bada_gpt/src/engine.js) のものを `build.js` が取り込みます。
