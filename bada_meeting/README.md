# Bada 思念会議 (BadaMeeting) — コンピュータ同士が会議するアプリ

コンピュータ同士がテキストのパケットをやり取りし、**企画・プランナー・アプリケーションエンジニア**の 3 役が会議形式で「何を作るか・どれだけかかるか・いつまでに作るか」を話し合って決めます。人は 3 つの方法 — **キーボード**、キー 1 つの長短で打つ**電鍵 (モールス符号)**、**ポインタの滞留** — のどれでも、複数行の発言を書いて会議に加われます。端末どうしは、**zone:// ウルトラネットワークの P2P 網** (主催者なし) か、**Bada Telegraph の音響電信** (音で送ってマイクで聞く) でやり取りします。Android / Windows 10・11 / Ubuntu / ブラウザで動き、依存なし・単一 HTML・サーバーなしです。

> **できないこと**
> - **思考を読み取る装置ではありません。** 入力はキーボード、電鍵 (キーの長短)、ポインタの滞留 (Ω-Telepathy と同じ「留めて選ぶ」方式) です。
> - **言語モデルは入っていません。** 3 役は、分野ごとの知識表と決まった計算式で発言を組み立てます。知識表にあるのは 7 分野 (メッセージング・販売・予約・学習・健康記録・業務管理・ゲーム) と一般用の 1 つです。
> - **zone の封印は秘密を守るものではありません。** 鍵は約 20 ビットで、仕組みを示すためのものです (WebRTC の通信路そのものは別に暗号化されています)。
> - **P2P 網で接続できるのは同じ LAN の中です。** インターネット越しの接続には対応していません。
> - 見積りと日程は目安です。実際の計画では担当者による確認が必要です。

## 会議の流れ

議題 (例: `スマホ向けの予約アプリを 3 か月で作りたい`) を送ると、各役割が議事録を読んで順に発言します。

| 役割 | すること |
|:--|:--|
| **企画** | 分野・対象・提供する価値・成功の指標・機能 (優先度つき) を提案。期限を超えたら、優先度の低い機能から次期に回す。最重要の機能は削らず、期限の延長を提案する |
| **アプリケーションエンジニア** | 構成 (クライアント・サーバー・保存)・主なデータ・機能ごとの工数を出し、対応環境の数と工程 (要件定義・設計・試験・公開準備) を上乗せして見積もる |
| **プランナー** | 見積りと期限を比べる。超えていれば企画に差し戻し、収まれば工程ごとの日程とリスク対策を組み、全員の合意を確かめて決定事項をまとめる |

例: `議題 → 提案 → 見積り (13.5 週間) → 懸念 (期限 13 週間を 0.5 週間超過) → 修正 (口コミを次期へ) → 再見積り (11.9 週間) → 日程 → 合意 → 合意 → 決定`

会議の途中で人が `期限を 12 週間にしましょう` と発言すると、議題を更新して話し合い直します。「議事録を保存」で、企画・設計と見積り・日程・リスク・発言の記録をまとめた Markdown を書き出します。

## 入力 — 複数行。キーボード・電鍵・ポインタのどれでも

発言欄は複数行です。3 つの方法は同時に使えます。すべての操作にキーが割り当ててあるので、ポインタなしでも全部できます。逆に、ポインタだけでも発言まで行えます。

| キー | 動作 |
|:--|:--|
| `Enter` | 改行 |
| `Ctrl+Enter` | 発言する (会議が始まっていなければ議題として送る) |
| `Ctrl+Shift+Enter` | 新しい議題として送る |
| `Alt+1` 〜 `Alt+8` | 予測した候補を入れる (定型句と、議事録に出てきた語句。最後の行の末尾から予測) |
| `Alt+0` | 「役割が自動で発言」を外しているとき、その役割の案を発言欄に入れる |
| `F2` | 電鍵モードの入 / 切 |
| `F3` | 和文 / 欧文の切り替え |
| `F4` | 音響電信の開始 / 停止 |
| `F6` | 議事録を保存 |
| `F7` | ポインタ (滞留) 入力の入 / 切 |
| `F8` | P2P 網 (zone) の画面を開く / 閉じる |

**電鍵 (モールス符号)**: 電鍵モードでは、発言欄で `Space` を短く押すと「・」、長く押すと「－」になります。少し間を空けると 1 文字が確定します。欧文の符号表は Bada Telegraph と同じで、和文モールス (濁点・半濁点は直前のかなに付く) にも対応します。`Enter` で改行できるので、電鍵だけでも複数行を書けます。1 単位の長さは 60〜300 ms で調整できます。和文モールスに小書きの字 (ゃ・っ など) は無いので、大きい字で入ります。

**ポインタ (滞留)**: 候補・かな盤・「発言する」「改行」「1 文字消す」「全部消す」の上にポインタを留めると確定します (クリックやタップでも確定)。かな盤には濁点・半濁点と改行があり、ポインタだけで複数行を書けます。確からしい候補ほど短い滞留で確定します (基準時間の 0.35〜1.6 倍。基準は 0.3〜2 秒で調整)。`F7` で切ると、留めても反応しなくなります。滞留が効くのは入力用の部品だけで、上部のボタン (役割・音響電信・接続・保存) は留めても動きません。

タッチ端末用に、押している長さで打てる「電鍵」ボタンも置いてあります (キーボードが無い端末のためのもので、キーボードがあれば使う必要はありません)。

## コンピュータ同士のやり取り (サーバーなし)

経路は 2 つあります。速くて確実なのは P2P 網 (WebRTC)、接続の手続きが要らないのは音響電信です。

### 音響電信 (Bada Telegraph) — 接続の手続きなし

`F4` を押すと、発言を **FSK 変調音**にしてスピーカーから鳴らし、ほかの端末がマイクで聞いて復調します。同じ部屋に置くか、通話 (スピーカーホン) 越しに使います。接続コードのやり取りは要りません。

- 変調方式とフレームは Bada Telegraph (`bada_telegraph`、ブランチ `claude/touch-sensitivity-app-packaging-ep1xmm`) と同じです: space 1000 Hz / mark 1600 Hz・100 baud、フレーム = プリアンブル + SOF `0x7E` + 長さ + 本体 + チェックサム。元の実装に対し、流しながらの復調、チェックサムの照合、雑音を信号と見なさない判定を加えています。
- 100 baud は遅い (毎秒 10 バイト) ので、**役割の発言は本文を送りません**。全端末が同じエージェントを持っているので、「誰が・何番目に・どの種類の発言をしたか」と発言文の SHA-256 の先頭 4 バイトだけを 15 バイトのパケットで送り (約 2 秒)、受け取った側が自分のエージェントで同じ発言を作ってハッシュを照合します。
- 議題と人の発言は UTF-8 の文章として送ります。複数行もそのまま届き、長い文章は部分に分けて送ります (日本語 60 文字で約 20 秒かかります)。
- 聞き逃しへの備え: 次の発言が聞こえなければ送り直します。先の番号の発言が聞こえた端末は、足りない番号を要求し、その発言をした端末が送り直します。
- 自分が送信している間は聞きません。ほかの端末が鳴らしている間は送信を待ちます。

### P2P 網 — zone:// ウルトラネットワーク (`F8`)

リポジトリ内の zone:// ウルトラネットワーク (`bada_gui_ide/browser/zone-lib.bada`、ZoneBrowser) の仕組み — 名前付け・リング型 DHT・貪欲な転送・結び目から導く Jones 鍵の封印 — を、実際のコンピュータ間通信 (WebRTC) の上で動かします。**主催者はいません。どの端末も対等です。**

| zone の仕組み | このアプリでの働き |
|:--|:--|
| 位置 `zone_id("peer:" + 名前)` (0〜4095 のリング) | 各端末のリング上の位置 |
| 隣接 = 次・前・2 つ先 (`peer_neighbors`) | 手でつなぐのは最初の 1 本だけ。端末の一覧をうわさで広げ、隣接へのリンクは網を通した合図の中継で**自動的に張る** |
| 貪欲な転送 (`zone_route`) | 宛先つきの電文を、宛先の位置に近い隣へ順に渡す。近づける隣が無ければ、重複を捨てながら全リンクへ広げる |
| 鍵に最も近いピアが持ち主 (`dht_nearest`) | 部屋 `zone://<部屋>.zone.jp/meeting` の鍵に最も近い端末が**担当**になり、発言に通し番号を付けて全員へ広げる。担当が抜けると、次に近い端末が引き継ぐ |
| 結び目 → Jones 鍵 → 封印 (`jones_key`, `zone_seal` / `zone_open`) | 部屋の結び目 (三葉 / 8 の字) を選ぶ。会議の電文は封印して送り、開けられない電文は捨てる。つなぐときにも同じ鍵の証明を求めるので、結び目の違う端末は網に入れない |
| `PUT` / `GET` | 議事録を `zone://<部屋>.zone.jp/minutes` に公開 / 取得。預け先は URL の鍵に最も近い端末。`200` / `404 zone-not-found` / `409 zone-guard-reject` |

- **元のコードとの照合**: アプリは起動時に、同梱した Bada 処理系 (`bada_gui_ide/www/bada.js`) で元の `zone-lib.bada` を実行して Jones 鍵を求め、JavaScript に移植した計算 (ID・鍵・担当・経路・封印) が元のコードと同じ値を返すことを確かめます。結果は `F8` の画面に表示されます。
- **つなぎ方**: `F8` で名前・部屋・結び目を決め、「① 招待コードを作る」→ 相手が貼って「② 返信コードを作る」→ 自分が貼って「③ 接続する」。どの端末からでも、網の中の誰につないでもかまいません。
- **二重発言の防止**: 担当は、役割の発言が議事録の続きとして正しいとき (自分のエージェントが作る発言と一致するとき) だけ番号を付けます。同じ役割の端末が 2 台あっても、発言は 1 回だけ採られます。
- **抜けるとき**: 画面を閉じると網に知らせます。予告なしに消えた場合も、接続が切れた時点で一覧から外します。
- **限界**: zone のレコード (公開した議事録) は預け先の 1 台だけが持ちます。その端末が抜けると失われます。端末の出入りの最中に発言が重なると、端末ごとの担当の見方が一瞬ずれて、番号が食い違うことがありえます。

どの経路でも、各端末に役割を 1 つ割り当てると、その端末のエージェントが自分の番に自動で発言します。「全役を 1 台で」を選べば 1 台だけでも会議が進みます。

## レポートのエントロピー方程式群の使い方

レポート *Entropy on manifold and differential of equation* (`system_transport.pdf`) に繰り返し現れる式を、発言の統計量に対応させています (`bada_claude/src/semantic.bada` と同じ対応)。

| 式 | 対応させた量 | 使い道 |
|:--|:--|:--|
| (E1) `x log x` | `S(p) = −Σ p log p` | 発言の情報量 H、議題とのずれ D (Jensen–Shannon) |
| (E2) `log(x log x) ≥ 2 (y log y)^{1/2}` | `x = e^H`、`y = e^D` | **門**: 通らない発言に「議題から外れている可能性」の印を付け、会議の文脈に加えない |
| (E3) `∫∫ 1/(x log x)² dx` | 候補の順位 r の事前分布 | 入力候補の確率と、ポインタの滞留時間 |
| (E4) 勾配二乗の汎関数 F | 発言ごとのずれ D の変化 | 会議の流れ (話題の飛びの少なさ) |

レポートは物理・幾何の文脈でこれらの式を述べており、会議や言語については定めていません。**どの量を x, y, f とみなすかは本アプリの設計上の選択**で、レポートから導かれた定理ではありません。計測は語の分布の統計であり、発言の内容が正しいかどうかは判定しません。

## 🧪 テスト

```sh
node bada_meeting/tools/test.js        # 単体テスト 83 件 (Node だけで動く)
node bada_meeting/tools/e2e-test.js    # 実ブラウザ 32 件 (Playwright + Chromium が必要。CI では実行しない)
node bada_meeting/tools/build.js       # src/ → index.html
```

- `test.js` は、zone の計算と元の `zone-lib.bada` の照合、模擬の 8 台での P2P 網 (自動リンク・主催者なしの会議・担当の引き継ぎ・遅れて加わる端末・zone レコード・結び目の違う端末の排除・中継)、モデムの変調 → 雑音 → 復調、電鍵の打鍵、音響空間での 3 端末の会議を確かめます。
- `e2e-test.js` は、4 つの画面を実際に WebRTC で一列につなぎ、網が残りのリンクを自動で張ること、主催者なしの会議で 4 台の議事録が一致すること、zone レコードの公開と取得、結び目の違う端末が入れないこと、担当の画面を閉じても引き継がれることを確かめます。操作はキーボードだけで行い、別にポインタの滞留だけでの入力と、音響電信の受信 (偽のマイク入力) も確かめます。

**確かめていないこと**: 別々の実機どうしを LAN でつないだ P2P 網 (テストは 1 台の中の複数の画面で行っています)。実際のスピーカーとマイクを通した端末間の音響通信 (部屋の反響、端末の音質、音量による影響)。Android では、マイクの権限をアプリの設定画面で許可する必要があるかもしれません (権限の宣言は入れてありますが、実機では未確認です)。マイクが使えない場合は送信のみになります。

## 📁 構成

```
bada_meeting/
├── index.html          # アプリ本体 (build.js の出力)
├── src/entropy.js      # エントロピー方程式群 (E1〜E4)
├── src/agents.js       # 3 役の能力: 分野の知識表・見積り・発言の組み立て
├── src/meeting.js      # 議事録・計測・役割の順番・計画書の書き出し
├── src/thought.js      # 入力: 電鍵 (モールス符号)・ポインタの滞留・候補の予測
├── src/telegraph.js    # Bada Telegraph の FSK モデムと、会議用の小さなパケット
├── src/acoustic.js     # 音響電信での送受信の規則 (送り直し・要求) と、スピーカー / マイク
├── src/zone.js         # zone:// の計算 (zone-lib.bada の移植) と、元のコードとの照合
├── src/p2p.js          # P2P 網: 一覧のうわさ・自動リンク・貪欲な転送・担当・封印・zone レコード
├── src/net.js          # WebRTC の接続コードと、切断の検知
├── src/ui.html         # 画面
├── tools/              # build.js / test.js / e2e-test.js
└── app/                # cordova (APK) / electron (EXE・AppImage・deb)
```

`build.js` は、SHA-256 を [`bada_gpt/src/engine.js`](../bada_gpt/src/engine.js) から、Bada 処理系と zone の実行系を [`bada_gui_ide/www/bada.js`](../bada_gui_ide/www/bada.js) と [`bada_gui_ide/browser/zone-lib.bada`](../bada_gui_ide/browser/zone-lib.bada) から取り込みます。
