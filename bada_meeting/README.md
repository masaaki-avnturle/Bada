# Bada 思念会議 (BadaMeeting) — コンピュータ同士が会議するアプリ

コンピュータ同士がテキストのパケットをやり取りし、**企画・プランナー・アプリケーションエンジニア**の 3 役が会議形式で「何を作るか・どれだけかかるか・いつまでに作るか」を話し合って決めます。人は**思念入力** (滞留で選ぶ入力) で会議に加われます。Android / Windows 10・11 / Ubuntu / ブラウザで動き、依存なし・単一 HTML・サーバーなしです。

> **できないこと**
> - **思考を読み取る装置ではありません。** 思念入力は、既存の Ω-Telepathy (`bio_medicine/omega_telepathy/`) と同じく「候補の上にポインタを留める」操作を入力に使い、予測で確定を速くする方式です。
> - **言語モデルは入っていません。** 3 役は、分野ごとの知識表と決まった計算式で発言を組み立てます。知識表にあるのは 7 分野 (メッセージング・販売・予約・学習・健康記録・業務管理・ゲーム) と一般用の 1 つです。
> - 見積りと日程は目安です。実際の計画では担当者による確認が必要です。

## 会議の流れ

議題 (例: `スマホ向けの予約アプリを 3 か月で作りたい`) を送ると、各役割が議事録を読んで順に発言します。

| 役割 | すること |
|:--|:--|
| **企画** | 分野・対象・提供する価値・成功の指標・機能 (優先度つき) を提案。期限を超えたら、優先度の低い機能から次期に回す。最重要の機能は削らず、期限の延長を提案する |
| **アプリケーションエンジニア** | 構成 (クライアント・サーバー・保存)・主なデータ・機能ごとの工数を出し、対応環境の数と工程 (要件定義・設計・試験・公開準備) を上乗せして見積もる |
| **プランナー** | 見積りと期限を比べる。超えていれば企画に差し戻し、収まれば工程ごとの日程とリスク対策を組み、全員の合意を確かめて決定事項をまとめる |

例: `議題 → 提案 → 見積り (13.5 週間) → 懸念 (期限 13 週間を 0.5 週間超過) → 修正 (口コミを次期へ) → 再見積り (11.9 週間) → 日程 → 合意 → 合意 → 決定`

会議の途中で人が `期限を 12 週間にしましょう` と発言すると、議題を更新して話し合い直します。「議事録を保存」で、企画・設計と見積り・日程・リスク・発言の記録をまとめた Markdown を書き出します。

## コンピュータ同士のやり取り (サーバーなし)

- 発言は **SHA-256 つきの JSON パケット**にして送ります。壊れたパケットや書き換えられたパケットは捨てます。
- 経路は **WebRTC データチャネル**です。「接続」で、主催者が招待コードを作る → 参加者が貼り付けて返信コードを作る → 主催者が貼り付ける、の手順でつなぎます (コードはメールやチャットで渡します)。
- 主催者が発言に通し番号を付けて全員に配るので、全員の議事録が同じ順序になります。
- 各端末に役割を 1 つ割り当てると、その端末のエージェントが自分の番に自動で発言します。「全役を 1 台で」を選べば 1 台だけでも会議が進みます。
- **既定では STUN サーバーを使わないので、接続できるのは同じ LAN の中です。** インターネット越しの接続には対応していません。

## 思念入力

- 候補・かな・「発言する」のどれも、**ポインタを載せて留めるだけで確定**します (クリックやタップでも確定)。キーボードでも入力できます。
- 候補は、定型句と、議事録に出てきた語句から予測します。
- 確からしい候補ほど短い滞留で確定します (基準時間の 0.35〜1.6 倍)。
- 「役割が自動で発言」を外すと、その役割の案が最初の候補に出ます。滞留で選んで、手直しして送れます。

## レポートのエントロピー方程式群の使い方

レポート *Entropy on manifold and differential of equation* (`system_transport.pdf`) に繰り返し現れる式を、発言の統計量に対応させています (`bada_claude/src/semantic.bada` と同じ対応)。

| 式 | 対応させた量 | 使い道 |
|:--|:--|:--|
| (E1) `x log x` | `S(p) = −Σ p log p` | 発言の情報量 H、議題とのずれ D (Jensen–Shannon) |
| (E2) `log(x log x) ≥ 2 (y log y)^{1/2}` | `x = e^H`、`y = e^D` | **門**: 通らない発言に「議題から外れている可能性」の印を付け、会議の文脈に加えない |
| (E3) `∫∫ 1/(x log x)² dx` | 候補の順位 r の事前分布 | 思念入力の候補の確率と、滞留時間 |
| (E4) 勾配二乗の汎関数 F | 発言ごとのずれ D の変化 | 会議の流れ (話題の飛びの少なさ) |

レポートは物理・幾何の文脈でこれらの式を述べており、会議や言語については定めていません。**どの量を x, y, f とみなすかは本アプリの設計上の選択**で、レポートから導かれた定理ではありません。計測は語の分布の統計であり、発言の内容が正しいかどうかは判定しません。

## 📥 ダウンロード (GitHub Actions)

**Actions** タブ → **BadaMeeting app build** → 最新の成功した実行 → ページ下部の **Artifacts**。

| アーティファクト | 中身 | 対象 |
|:--|:--|:--|
| `badameeting-android` | `bada-meeting-debug.apk` | Android 7.0 以上 |
| `badameeting-windows` | `BadaMeeting-*-x64.exe` (インストーラ) / `BadaMeeting-*-portable.exe` | Windows 10 / 11 (x64) |
| `badameeting-linux` | `BadaMeeting-*-x86_64.AppImage` / `BadaMeeting-*-amd64.deb` | Ubuntu (x64) |

ブラウザ版は [`index.html`](index.html) を保存して開きます。APK はデバッグ署名、EXE はコード署名なしです。

## 🧪 テスト

```sh
node bada_meeting/tools/test.js        # 単体テスト 37 件 (Node だけで動く)
node bada_meeting/tools/e2e-test.js    # 実ブラウザ 13 件 (Playwright + Chromium が必要。CI では実行しない)
node bada_meeting/tools/build.js       # src/ → index.html
```

`e2e-test.js` は、3 つの画面を実際に WebRTC でつなぎ、企画・エンジニア・プランナーを別々の画面に割り当てて会議させ、3 つの議事録が完全に一致することを確かめます。

## 📁 構成

```
bada_meeting/
├── index.html          # アプリ本体 (build.js の出力)
├── src/entropy.js      # エントロピー方程式群 (E1〜E4)
├── src/agents.js       # 3 役の能力: 分野の知識表・見積り・発言の組み立て
├── src/meeting.js      # 議事録・計測・役割の順番・計画書の書き出し
├── src/thought.js      # 思念入力: 候補の予測と滞留時間
├── src/net.js          # パケットと WebRTC (接続コード方式)
├── src/ui.html         # 画面
├── tools/              # build.js / test.js / e2e-test.js
└── app/                # cordova (APK) / electron (EXE・AppImage・deb)
```

SHA-256 は [`bada_gpt/src/engine.js`](../bada_gpt/src/engine.js) のものを `build.js` が取り込みます。
