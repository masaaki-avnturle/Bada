家の電力線を物理層にするL0 · Panasonic HD-PLC · IEEE 1901 ウェーブレット OFDM

分電盤から各部屋へ伸びる屋内配線を、そのまま通信路として使います。2–28 MHz を 512 本の サブキャリアに分け、各サブキャリアの SNR に応じて 1〜5 ビットを割り当てる 適応ビットローディングを行います。アマチュア無線帯にはノッチを入れて送信しません。

リンク状態

サブキャリア配分上: SNR [dB] / 下: 割当ビット数

緑の面が各サブキャリアの SNR、下の棒が 割当ビット数(0〜5 = 2〜32 PAM)。 赤い帯はアマチュア無線帯のノッチで、ここは送信しません。多重経路の反射で SNR が落ち込む位置(櫛形フェージング)では自動的にビット数が下がります。

zone アドレスを NTT の電話番号へ写像するL1 · 写像 φ

zone:// のアドレスを、NTT の番号計画上の実在形式へ写します。リング上の位置 zone_id が市外局番を決め(近い zone は近い局番になる)、 加入者番号は URL のハッシュから採ります。番号ポータビリティと同じ割当表を持つので φ⁻¹ は厳密な逆写像になります。

呼制御と音声帯モデム16-QAM · fs 8 kHz · 搬送波 2 kHz · 2000 baud

メタル回線は音声帯しか通しません。そこで封筒バイト列を 16-QAM に変調して 300–3400 Hz に収めます。搬送波が標本化周波数のちょうど 1/4 なので cos/sin が {1,0,−1,0}/{0,1,0,−1} の 厳密な直交系になり、相関復調が誤差なしで成立します。
受信コンステレーション。16 点の格子上に乗っていれば復調成功です。

LINE / Instagram をウルトラネットワークに取り込むL4 · メッセージ多重化

取り込みは各社が公開している公式 API の仕様どおりに行います。LINE は Messaging API の Webhook と reply/push、Instagram は Instagram Graph API の Webhook と /<IG_ID>/messages です。受信本文は HMAC-SHA256 の署名検証を本物の計算で通します。

実運用では各プラットフォームで発行したチャネルシークレット / アクセストークンが必要です。 資格情報が無いこの画面では、公式仕様と同じ形の本文を組み立てて署名経路まで本物を通す ローカル模擬で動作します。非公開 API の解析や認証の迂回は行いません。
