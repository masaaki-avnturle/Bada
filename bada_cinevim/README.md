# 🎬 Bada CineVim — 映画カウントダウンの VIM エディタ

**量子プログラミング言語 Bada 用の、映画的な VIM エディタ。**
**ポインタやカーソルが指した位置が、その場でどアップ**になります。**拡大鏡は要りません。**
**右へ動かせば、どアップは右へ滑り、左へ戻せば左へ戻ってきます。** 指した位置から離れるほど
文字はもとの大きさに戻る、二軸の魚眼です。

依存ゼロ・単一 HTML・オフライン動作。`index.html` をダブルクリックするだけで起動します。

## 🔎 ポイント位置のどアップ — 右へ左へ、焦点が滑る

文書は**空行で段落**に、1 行は**語のまとまり(セグメント)** に分かれます。
セグメントがどアップの最小単位です。

### 二軸の魚眼

焦点からの距離で倍率が決まります。**縦は行の距離**、**横は px の距離**で、
どちらも同じ式です:

```
scale = 1 + (zpeak − 1) · exp(−d² / 2σ²)
```

行 `i`、セグメント `j` の倍率は、縦の効きと横の効きの積になります:

```
s(i,j) = 1 + (zpeak − 1) · exp(−(i−focusRow)² / 2·vspread²)
                         · exp(−(cx_j − focusX)² / 2·hspread²)
```

`cx_j` は**拡大していないときの**セグメント中心です。拡大後の位置で測ると、
焦点が自分の作った拡大に押しのけられて暴れるため、距離は必ず自然位置で測ります。

### 重ならない配置

拡大したぶんの余白を前後へ配り直します。**縦にも横にも同じ関数**が効きます:

```
offsets[i] = Σ_{j<i} size_j(k_j − 1) + size_i(k_i − 1) · anchor
```

`anchor` は拡大の基準点で、**縦は 0.5**(中心から拡大)、**横は 0**(左端から拡大 =
`transform-origin: 0`)。「要素 i の終わり ≤ 要素 i+1 の始まり」が成り立つことを、
縦横それぞれテストで検証しています。マージンを動かさず `transform` だけで済むので、
**毎フレームのレイアウト再計算が起きません**。

### ポインタ位置の逆変換

拡大すると文字の位置がずれるので、ポインタの当たり判定を素直に取ると焦点が振動します。
そこで**表示位置から自然位置へ逆に解いて**狙いを決めます:

```
displayToNatural(lefts, widths, scales, dx) -> セグメントの添字
```

縦も同じで、前フレームのずらし量から行を逆算します。おかげで、拡大が焦点を
押しのけることがありません(逆変換が単調であることもテストしています)。

| 操作 | 効果 |
|:---|:---|
| **ポインタを動かす** | 指した位置がその場でどアップ。**右へ左へ動かすと追ってくる** |
| **`h` `l` / `w` `b`** | カーソルを左右へ。どアップもその位置へ滑る |
| **`j` `k` / `}` `{`** | 行と段落を上下へ。どアップがその行へ移る |
| **クリック / タップ** | そこへカーソルを移す |
| **Ctrl + ホイール** | どアップの倍率(1.4× 〜 4.4×) |
| **ホイール** | 文章をスクロール |

| コマンド | 効果 |
|:---|:---|
| `:mag` | どアップの ON / OFF |
| `:prose` / `:code` | 文章ビュー / コードビュー(等幅) |
| `:set zpeak=2.8` | どアップの最大倍率 |
| `:set vspread=2` | 縦の効き(行数) |
| `:set hspread=140` | 横の効き(px) |
| `:set nodim` | まわりの行を暗くしない |

拡大した行が画面からはみ出すときは、焦点セグメントが見えるように横へ追従します。
行がまるごと収まるときは動かしません。

内側の構造は**行のまま**です。各セグメントは `.seg[data-l][data-c0]` として
行と桁を保持するので、**VIM のモーションもオペレータもそのまま効きます**。

**日本語入力(IME)に対応しています。** 日本語は `keydown` では文字が取れないため、
変換中のキーは素通しし、確定した文字を `input` / `compositionend` で受け取ります。

## 🎥 三つの映画的演出

### 1. どアップ フォーカス (被写界深度) — コードビュー

カーソル行 — **ポイントされた文章** — が最大 **2.6 倍**に拡大され、離れた行ほど
ガウス核 `k = exp(-d²/2σ²)` で **縮小・ぼかし・減光**されます。映画のレンズが
一行だけにピントを合わせ、前後がボケて流れる、あの画です。

`:code` のコードビューで効く、行単位のどアップです(文章ビューでは上の魚眼が担当します)。

| コマンド | 効果 |
|:---|:---|
| `:focus` | どアップの ON / OFF |
| `:flash` | イベント処理フラッシュの ON / OFF |
| `:bus` | イベントバス HUD の表示切替 |
| `:emit [名前]` | 現在行へ手動で `SIGNAL` を発行 |
| `:set peak=3.2` | 最大倍率 (既定 2.6) |
| `:set spread=1.4` | 焦点の狭さ = 被写界深度の浅さ (既定 2.2) |
| `:set maxBlur=5` | 背景のぼかし量 (既定 3.2) |
| `:set depth=0.5` | 演出全体の強さ 0〜1 |

拡大した行が重ならないよう、行の占有高さは `baseH × scale` で再計算され、
カーソル行の中心が常に画面中央に来るようドキュメント全体が追従します。

### 2. イベント処理のフラッシュ効果

エディタの操作は**すべてイベント**になります。1 キー入力 = 1 ディスパッチで、
`key` → ハンドラのイベント (`motion` / `edit` / `ex` / `search` …) → `mode` の順に
イベントバスへ積まれ、UI がその順にディスパッチして**対象行を光らせます**。

ディスパッチされた行に起きること:

- **行が発光する** — 種別の色で下地が光り、文字がにじむ
- **処理の光が行を左から右へ走る** (`sweep`)
- **左端にイベントマーカー**が立つ
- 行が**わずかに浮く** (7px — 跳ね上げではなく「処理中」の微差)
- ぼかしが一時的に**解除**され、処理対象がはっきり見える
- 種別ごとの**短いブリップ音**が鳴る (色相と同じ並びで音程が決まる)

包絡は信号ランプと同じ **「速い立ち上がり → 指数減衰」**:

```
shape = t < 0.12 ? t / 0.12 : exp(-(t - 0.12) · 5.2)
env   = shape · (1 - t) · intensity
```

`t = 0.12` でピーク、`t = 1` で完全に消灯します。画面の揺れ・色収差・衝撃波・破片は
ありません。

#### イベント種別

| 種別 | 色 | 発生する操作 |
|:---|:---|:---|
| `KEY` | シアン | すべてのキー入力 (1 キー = 1 件) |
| `MOTION` | 水色 | カーソル行の移動 (`j` `k` `G` `}` `%` タップ…) |
| `EDIT` | 緑 | 本文の変更 (`x` `dd` `p` `o` 挿入…) |
| `MODE` | 紫 | モード遷移 (`i` `v` `:` `Esc`…) |
| `EX` | 金 | Ex コマンドの実行 |
| `SEARCH` | 桃 | `/` `?` の一致ジャンプ |
| `SIGNAL` | 黄 | `Space` / `:emit` の手動発火 |
| `TICK` | 橙 | カウントダウンの秒刻み |
| `RUN` | 青緑 | 量子 Bada の実行完了 |
| `IO` | 黄緑 | ファイルの読み書き |
| `ERROR` | 赤 | 実行エラー |

#### イベントバス HUD

画面左下に**直近 7 件**のイベントが積まれ、処理中のものが光ります
(種別 / 対象行 / 内容)。右下には**スループット** (`ev/s`)、**累計ディスパッチ数**、
**処理中の件数**が出ます。`:bus` で表示を切り替えられます。

`:flash` で**フラッシュだけ**を切っても、**イベント処理そのものは止まりません** —
バスのログとスループット計は動き続けます。

### 3. 映画のカウントダウン

`:countdown 5` または **⏱ カウントダウン** ボタンで、**アカデミー・リーダー**が起動します。
同心円・十字の走査線・掃引する指針・フィルムグレイン・縦キズつき。
**1 秒刻むたびに `TICK` イベント**がバスへ投入され、残り秒が減るほど強くなります。
**T-0 では全画面フラッシュ**が走ります。

## ⚛ 量子 Bada ランタイム

`:run` または **▶ 実行** でバッファを量子 Bada として実行します。
**状態ベクトルシミュレータ**(最大 14 量子ビット)を内蔵しています。

```bada
qubit q[3];

H q[0];              // 重ね合わせ  |0⟩ → (|0⟩+|1⟩)/√2
CNOT q[0], q[1];     // もつれ      → ベル状態 Φ+
X q[2];
RY q[2], 0.7;        // 回転ゲート (RX / RY / RZ)

let shot = measure q;   // 観測して collapse
print shot;

let zeta = 4.0 <- 2.0;  // 非可換左作用 π(χ,x)
let area = 2.0 -< 12.0; // 多様体積分 ∬1/(x·log x)²
let grad = 1.0 >- 0.5;  // 量子作用素右作用 ⊕(iℏ∇)^⊕L
print beta(2, 3);       // β(p,q) = Γ(p)Γ(q)/Γ(p+q)
```

実行後は終状態 |ψ⟩ の確率分布が出力パネルに並びます。

### 三つの非可換オペレータの数値意味論

| 演算子 | 数学的対応 | 実装 |
|:---|:---|:---|
| `<-` | `π(χ,x) = [iπ, f(x)]` | `a·cos(b) − b·sin(a)` — 交換子の実数表現 (非可換) |
| `-<` | `∬ 1/(x·log x)² dx` | 区間 `[a,b]` のシンプソン則による数値積分 (向きで符号反転) |
| `>-` | `⊕(iℏ∇)^⊕L` | `ℏ · (sin(a+b) − sin(a)) / b` — ℏ 倍の数値勾配 |

`Γ(s)` は Lanczos 近似、`β(p,q) = Γ(p)Γ(q)/Γ(p+q)`、`ζ(s) = β(p,q)/log x`。
ゲートは `H X Y Z S T` / `CNOT CZ SWAP` / `RX RY RZ`。
観測は種つき擬似乱数 (mulberry32) なので、同じ種なら結果が完全に再現します。

## 🧪 テスト

```sh
node bada_cinevim/tools/engine-test.js
```

`index.html` のインライン `<script>` を Node の `vm` で読み込み、**467 件**を検証します —
トークナイザ、Γ/β/ζ、三つのオペレータ、量子シミュレータ (ベル状態・ユニタリ性・collapse)、
式パーサの優先順位、プログラム実行、VIM のモーション・オペレータ・`.` リピート・
ビジュアル・Ex コマンド、**イベントバス** (`key` が必ず先頭に来ること、`seq` の単調増加、
同じ行の移動では `motion` が出ないこと、`o` が `edit` を二重発行しないこと、種別ごとの
色相が決定的であること)、そしてシネマ数理 (フォーカス減衰の単調性、行が重ならない
レイアウト、フラッシュ包絡の立ち上がりと単調減衰・線形スケール・境界、
カウントダウンの単調減少)、そして**段落・語・魚眼**(全行が段落か隙間に必ず含まれること、
送り仮名を含む語の切り出し、**セグメントを連結すると元の行に戻ること**(取りこぼしなし)、
倍率が焦点で最大・左右対称・遠方で等倍に戻ること、**拡大しても要素が重ならないこと**
(縦の中心基準と横の始点基準の両方)、**表示位置→自然位置の逆変換が正しく、かつ単調で
後戻りしないこと**)。

## 📁 構成

```
bada_cinevim/
├── index.html              アプリ本体 (依存ゼロ・単一 HTML)
├── app/
│   ├── cordova/config.xml  Android APK のラッパー設定
│   └── electron/           Windows EXE / Ubuntu AppImage・deb のラッパー
└── tools/engine-test.js    エンジン単体テスト (Node)
```

アプリ本体は `index.html` ただ一つです。各プラットフォーム版は、この HTML を
`www/` として同梱するだけの薄いラッパーで、ロジックは完全に共有されています。
