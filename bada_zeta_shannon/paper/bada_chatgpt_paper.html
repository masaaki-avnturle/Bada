要旨

本稿は、未知事前エンジン（Unknown-Prior Engine）の上に作られた対話システム「Bada ChatGPT」（コードネーム Bada XP）の仕組みを記述する。システムは三層からなる。最下層は位相コア ψi = √ai·exp(iθi) と追記専用台帳であり、零の保存と |ψ|² = a という二つの初等的な定理を持つ。中間層は、シャノンの公式をゼータ関数に三通りに用いる言語化エンジンで、量子プログラミング言語 Bada だけで書かれている。最上層は、外部の大規模言語モデルへ問い合わせるバージョン台帳（Fable 5 からローカル分派まで）である。

ローカルのエンジンについて、13 項目の自己認証がすべて通ること、台帳内の質問 20 問のうち 16 問で期待した事実を第一位に返すこと、台帳外の質問 10 問のうち 9 問で「わかりません」と棄権することを実測した。

題に掲げた「Claude Fable に匹敵する」については、結論を先に述べる。ローカルのエンジンは Fable に匹敵しない。約 75 個の事実を検索して答える仕組みであり、推論・作文・翻訳・プログラム生成はできない。システムが Fable と同じ水準の答えを返すのは、バージョン台帳の最上段が Fable 自身を呼び出す場合だけである。ローカルのエンジンが持つのは能力ではなく、根拠の追跡可能性、証拠がないときの棄権、決定的な再現性という別種の性質である。

本稿の位置づけ。本稿は仕組みの記述であって、性能の主張ではない。標識は従来の巻と同じく 証明済（証明があり数値でも確認）、 検証済（実装を実行して確認）、 未検証（本稿では確かめていない）、 否定（成り立たないことを確認）を用いる。リーマン予想について本稿は何も証明しない。

1　はじめに

先行する手稿群は、Bada を「未知事前エンジンをランタイムとする言語」として定めた。エンジンは最大エントロピーの無知から出発し、証拠を追記専用の台帳に積むことで確信を得る。本稿が扱うのは、その上に作った対話システムである。構成要素は次の三つで、いずれもリポジトリに実装がある。

  1. 未知事前エンジン（位相コアと台帳）。処理系 bada_gui_ide/www/bada.js のネイティブ関数 softmax、cognitive_system、update、unknown_prior として提供される。
  2. ゼータ＝シャノン言語エンジン（bada_zeta_shannon/zeta_shannon.bada、純 Bada、約 1,300 行）。質問に根拠つきで答え、会話から学習し、文章を生成する。
  3. バージョン台帳とブリッジ（bada_ruby/lib/bada/lang/llm.rb）。外部の言語モデル API に問い合わせ、失敗時はローカル段に落ちる。

2 と 3 は別々に作られたが、本改訂で接続した。台帳のローカル段では、まず 2 の Bada 製エンジンが答え、証拠がなく棄権したときだけ Ruby 製の OmegaChat に渡る。接続の方法は第 6 節と第 7 節で述べる。

2　全体構成

3　未知事前エンジン

3.1　位相コア

語彙（あるいは候補の集合）の大きさを V とする。ロジット z ∈ RV から基底分布 a = softmax(z) を作る。モジュール m は確率分布 q(m) と位相ベクトル φ(m) の組であり、そのシャノンエントロピーを Hm = −Σj qj(m) log qj(m)、利得を βm と書く。位相コアは次で定義される。

θi = Σm βm Hm φi(m),　　ψi = √ai · exp(iθi),　　q̂i = |ψi|² / Σj |ψj|²

定理 1（零の保存） 証明済　ai = 0 ならば、モジュールと利得の選び方によらず q̂i = 0 である。
証明。ψi = √0 · exp(iθi) = 0 であり、0 に何を掛けても 0 である。∎
定理 2（位相は確率を変えない） 証明済　すべての i で q̂i = ai である。
証明。|exp(iθi)| = 1 より |ψi|² = ai。Σj aj = 1 なので正規化は恒等である。∎

実測では、6 候補のうち 2 つを除外した分布で零が 2 つとも保存され、|ψ|² と a の最大偏差は 5.55×10−17 であった（第 8 節 Z10）。

定理 2 には裏の意味がある。位相 θ は出力分布にまったく影響しない。エントロピー位相は台帳に記録されるが、振幅を足し合わせる操作がない限り確率には現れない。したがって位相コアは、モジュールを「壊さずに重ねる」ための安全装置であって、答えを良くする装置ではない。本システムで答えの順位を決めているのは、第 4 節の重みと信念である。

3.2　未知事前分布と台帳

事前分布は一様分布 u = (1/V, …, 1/V) から始める。これは制約のない場合の最大エントロピー分布である。証拠 e が届くと、学習率 λ で

prior ← normalize( (1 − λ)·prior + λ·e )

と更新し、結果を台帳に追記する。台帳（TupleSpace）は追記専用で、事実は上書きされない。推論の履歴がそのまま監査の記録になる。

更新のたびにエントロピーが下がることは定理ではない。証拠が事前分布より平らであれば上がる。本稿のデモでは、話題の信念のエントロピーが 2.6391 nat（一様）から 13 回の対話で 2.1662 nat に下がった 検証済。

4　ゼータ＝シャノン言語化

シャノンの公式 H = −Σ p log p を、ゼータ関数に関わる三つの場所で用いる。

4.1　ナッシュ・シャノンゼータ

最初の N 個の素数 p1, …, pN に確率 qk(σ) = pk−σ / Z(σ)、Z(σ) = Σk pk−σ を割り当てる。これは平均 log p を固定したときの最大エントロピー分布であり、エントロピー正則化ゲームの均衡である。そのエントロピーを H(σ) とし、

ζNS(s) = ζ(s) · exp( iβ H(Re s) )

と定める。

命題 3 証明済　すべての s で |ζNS(s)| = |ζ(s)| であり、ζNS と ζ の零点は一致する。加法版 ζ(s) + H(Re s) は ζ の零点で値 H ≠ 0 を取るので、零点を保存しない。
証明。H は実数なので |exp(iβH)| = 1。後半は代入による。∎

これは定理 1・2 と同じ事実（絶対値 1 の因子は零も絶対値も変えない）の言い換えである。N = 40 で H(1/2) = 3.4568、H(1) = 2.6986 となり、先行稿の値を再現した。ζ は Borwein の η 級数（n = 50）で計算し、10 < t < 35 の零点 5 個を小数 6 桁まで得た。命題 3 はリーマン予想と無関係である。

4.2　ジップ＝ゼータ則による単語の重み

ジップの法則は、頻度順位 r の単語の確率が r−s に比例すると述べる。有限の語彙 V では

P(r) = r−s / ZV(s),　　ZV(s) = Σr=1V r−s

であり、V → ∞、s > 1 で ZV(s) → ζ(s) となる。この分布のもとで順位 r のトークンの自己情報量は

I(r) = −log P(r) = s·log r + log ZV(s)

である。エンジンは、台帳のトークンを文書頻度で順位づけし（同順位は中央順位で代表）、指数 s を最尤法で求める。検索の重みには、最頻トークンに対する超過分

w(r) = I(r) − I(1) = s·log r

を使う。log ZV(s) が消えるので、機能語の重みはほぼ 0、珍しい語の重みが最大になる。台帳にないトークンは順位 V + 1 に置く。現在の台帳では s ≈ 0.55、V = 1,653 であった。

トークンは、ASCII の単語と、隣り合う全角文字のバイグラムである。日本語では内容語が漢字・片仮名、文法要素が平仮名で書かれるので、すべて平仮名のバイグラムには係数 0.2、平仮名を一つ含むものには 0.5 を掛ける。これは経験則であり、形態素解析の代用である。

4.3　質問から答えまで

質問 Q と事実 Di のトークン集合に対し、

ci = Σt∈Q∩Di w(t)² / √( Σt∈Di w(t)² · Σt∈Q w(t)² )

zi = G·ci（共有トークンがあるとき）、　zi = −800（ないとき）

とする（G = 22）。exp(−800) は倍精度で厳密に 0 になるので、証拠を共有しない事実は a = softmax(z) で確実な零になり、定理 1 によって以後どの段でも復活しない。

次に位相コアを通し（q̂ = a）、会話の信念 b（話題上の分布）との積を取る。

ri ∝ q̂i · b(topic(i))1/4

b は一様分布との混合で更新されるので常に正であり、この積も零を保存する。r の第一位と、その 0.6 倍以上の第二位までを答えとして出力し、標識と出典を付ける。

棄権。被覆率 κ = maxi Σt∈Q∩Di w(t)² / Σt∈Q w(t)² が 0.2 未満なら、答えを出さずに「わかりません」と返す。未知のトークンは最大の重みを持つので、台帳にない話題の質問は κ が小さくなる。

4.4　生成とナッシュ温度

文章生成は文字 4-gram（3 文字の文脈、なければ 2 文字に後退）である。文脈に続く候補を出現回数の降順に並べ、順位 k の候補に素数ゲームの均衡重みを掛ける。

wk ∝ countk · pk−σ

σ = 0 で元の頻度、σ が大きいほど第一候補に集中する。非零の因子なので、その文脈で一度も現れなかった文字は確率 0 のままである。既定は σ = 1/2 とした。

5　量子層

先行の論文集は、位相コアのゲート層が確率ベクトルだけを受け渡し、干渉を表現しないことを指摘した。本エンジンはその修正を含む。レジスタを複素振幅ベクトルとして保持し、アダマールを 2×2 の線形写像として作用させる。H·H = I が成り立ち（P(|000⟩) = 1.000000）、Grover の振幅増幅が動く。64 状態・印 1 個で 6 反復後の成功確率は 0.9966 であった 検証済。

答えの選択では、位相コアが選んだ事実に印を付けてオラクルとし、増幅後の確率を表示する。これには三つの限界がある。

  • 古典計算機上のシミュレーションであり、量子計算機を駆動しない。
  • オラクルは答えが決まった後に作られる。探索は答えを見つけておらず、増幅を示しているだけである。
  • 本物のアダマールは H|0⟩ に |1⟩ 成分を生むので、零の保存と万能量子計算は両立しない。エンジンは答えの決定には零を保存する位相コアを使い、量子レジスタは別に扱う。

6　バージョン台帳とブリッジ

Ruby 側の Bada::Lang::LLM は、外部の言語モデル API への橋である。環境変数に API 鍵があれば Anthropic Messages API または OpenAI 互換 API を呼び、なければ nil を返す。呼び出し側は nil を受けるとローカル分派に落ちる。通信エラー、JSON の解析失敗、安全分類器による拒否も同じく nil に丸める。鍵は環境変数からのみ読み、保存も出力もしない。

モデルは台帳から選ぶ（図 1 上段）。既定はムートスで、Chat.downgrade(n)、Chat.upgrade(n)、Chat.use(id) で段を移る。最下段 local に固定すると、鍵があってもローカル分派だけで動く。

ローカル段。ローカル段は二つのエンジンを順に呼ぶ。最初に第 4 節の Bada 製エンジンが答える。台帳に証拠があれば、その答えに標識・出典・確信度を付けて返す。棄権した場合の扱いは環境変数 BADA_LOCAL_ENGINE で決まる。既定の auto では OmegaChat に渡し、zeta では「わかりません」をそのまま返し、omega では Bada 製エンジンを使わない。

注意すべき点がある。auto では、棄権という性質がシステム全体としては失われる。OmegaChat は証拠の有無に関係なく文章を生成するからである。根拠のある答えだけを通したい場合は zeta を選ぶ必要がある。

OmegaChat は五段の処理を行う。質問のシャノンエントロピーと多様体エントロピー不変量を測り、回転体上で誤差修正し、キーワードと不変量でコーパスを検索し、目標エントロピーで文章を生成し、やり取りを台帳に記録する。

台帳最上段のモデル ID は claude-fable-5 と書かれている。本稿の作業環境には API 鍵がなく、この ID で実際に応答が得られるかは確かめていない 未検証。

接続のテストは 11 件を追加し、Ruby 側の全 231 件が通った。対象は、根拠つきの答え、棄権、学習の持続、local 固定時の動作、三つのモード、node やエンジンが欠けたときのフォールバックである。

8.2　質問応答の評価

台帳内の質問 20 問と台帳外の質問 10 問を用意し、質問ごとに新しいセッションで評価した（paper/eval.js）。台帳内は、答えの中に期待した事実の一部が含まれるかで判定した。

質問の種類問数期待どおり誤り
台帳内（期待する事実を返す）2016（80%）4（別の事実を返した）
台帳外（棄権する）109（90%）1（無関係な事実を答えた）

台帳内の誤り 4 問は、いずれも同じ話題の別の事実を返したものである。たとえば「ホッジ予想は解けていますか」に対し、「ホッジ予想は未解決である」ではなく「p = 1 の場合は証明済みである」を返した。問いの意図を読んでいないことがわかる。台帳外の誤りは「カレーの作り方を教えて」で、「作り」「方を」といった一般的なバイグラムの一致が被覆率の閾値を越え、ポアンカレ予想の事実を答えた。

この評価の限界は大きい。質問は台帳を書いた者が作っており、言い回しが台帳に近い。問数も 30 と少ない。数値は仕組みが動くことの確認であって、一般の質問に対する性能の推定ではない。評価後に閾値や台帳を調整することはしていない。

9　Claude Fable との距離

「Fable に匹敵する」という言い方には三つの読み方がある。それぞれについて、成り立つかどうかを分ける。

読み方判定内容
(a) ローカルのエンジンが能力で並ぶ否定ローカルのエンジンは約 75 個の事実から一つか二つを選んで返す。学習されたパラメータはなく、文の意味を扱わない。推論、要約、翻訳、作文、プログラム生成はできない。台帳にない話題には答えられない。Fable は大規模に学習された言語モデルであり、同じ尺度には乗らない。
(b) システム全体が Fable の水準で答える未検証バージョン台帳を最上段にして API 鍵を与えれば、答えるのは Fable 自身である。これは「匹敵」ではなく「同一」であり、Bada 側の寄与は経路の選択とフォールバックである。本稿では鍵がなく実行していない。
(c) ローカルのエンジンに固有の性質がある検証済下の表の性質は仕組みから従う。能力の比較ではなく、設計の違いである。

除外の不可逆性証拠を共有しない事実は以後のどの段でも選ばれない定理 1

これらは小ささの裏返しでもある。根拠が追跡できるのは、答えが台帳の文の写しだからである。同じ理由で、台帳にない正しい答えは決して出てこない。

ローカルのエンジンを Fable の水準に近づける道は、本稿の仕組みの延長にはない。事実を増やせば答えられる範囲は広がるが、検索であることは変わらない。位相コアの二つの定理は安全の性質であり、能力を生まない（定理 2）。能力に必要なのは大規模な学習であり、それはソースコードの工夫で代えられない。

10　限界

  • 理解しない。言い換え、否定、問いの意図を扱えない。8.2 節の誤りはすべてこれに由来する。
  • 生成は継ぎ合わせである。4-gram の出力は台帳の文の断片であり、継ぎ方によって事実と違う文になる。実際に「ゼータは準同型ではなく、統一場は達成ではない。」という文が出た。生成の出力には標識を付けていない。
  • 棄権は保証でない。一般的なバイグラムの一致で閾値を越えることがある（8.2 節）。
  • 位相は答えに寄与しない。ナッシュ・シャノン位相は記録されるだけである（定理 2）。
  • 量子部分はシミュレーションである。第 5 節のとおり。
  • 既定のモードでは棄権が通らない。auto では棄権した質問を OmegaChat が引き取り、証拠なしに文章を生成する（第 6 節）。
  • 接続には node が要る。Bada 製エンジンは JavaScript 製の処理系で動くので、Ruby だけの環境では OmegaChat だけになる。
  • 評価が小さい。30 問、作成者自身による出題である。

11　結論

Bada ChatGPT は、位相コアと追記専用台帳の上に、ゼータ＝シャノン則で重みを付けた検索応答と、外部モデルへのバージョン台帳を重ねたものである。仕組みは三つの初等的な事実に支えられている。絶対値 1 の因子は零を保存する。ジップの法則はゼータ分布であり、その自己情報量が単語の重みになる。未知のトークンは重いので、知らない話題は被覆率で検出できる。

ローカルのエンジンは Claude Fable に匹敵しない。持っているのは、小さな範囲で根拠を示して答え、範囲の外では黙るという性質である。システムが Fable の水準の答えを返すのは、台帳が Fable を呼ぶときに限られる。

本改訂で、Bada 製エンジンをバージョン台帳の local 段に接続した。次の一手は二つある。台帳最上段の到達性を鍵のある環境で確かめること。第三者が作った質問で 8.2 節の評価をやり直すことである。
