## 要旨

BadaGPT電信は、思考入力 (無音の口形・脳波 BCI・描いた動き・本人の体のサイン・画像・文字) から依頼の全体を捉え、アプリケーション・ソースコード・論文を生成して Android / Windows / Linux 向けに自動コンパイルする生成系である (第 1 版)。本稿は、この系を ChatGPT のような対話生成系へ育てるための**版の梯子**を定義し、その第 2 版を実装して測る。版は「能力・検証電池・境界」の三つ組として定義し (定義 1)、以後の版はそれ以前のすべての電池に合格しなければならない (単調性)。すべての版に三つの不変条件を課す: (i) **零の保存** — 補助的な情報は主たる情報を位相でしか変えられず、確信した零を復活させない (山口フレームワークの文献 [11][22] の原理 1・命題 1)、(ii) **追記のみ** — 事実は積み上がるだけで上書きされず、除外や取り消しも事実として残る (文献 [21][22] の TupleSpace)、(iii) **標識付き主張** — 出力に含まれる数理は文献集 [9] の標識 (証明済 / 古典・検証済 / 未検証 / 予想) を伴い、未検証の式は可視化にとどめる。第 2 版として**会話台帳と仕様の研ぎ澄まし**を実装した: 発話・読み取った仕様・除外・項目の増減・錬成・やり直しを凍結された事実として追記し、いまの仕様は台帳の投影として再計算される。モジュールへの信念は一様 (最大エントロピー・未知事前) から始まり台帳の証拠で尖る。16 対話の多ターン評価で、投影は最終仕様の完全一致 93.8% (発話を連結して 1 回で把握する基準法は 62.5%)、投影した仕様から生成したアプリの静的検証合格率 100%、未知事前のエントロピーは平均 1.51 bit 低下した。単体テストは 257 件すべて合格し、実ブラウザで追加・除外・やり直し・再読み込み後の保持・新しい会話を確認した。第 3〜23 版は五つの時代 (対話・学習・自律・身体・自己記述) に分けて、理論・工学・検証電池・境界を一段ずつ与える。「第 23 版」は本稿が定義する能力段階の名であり、OpenAI の製品の版番号との対応を主張するものではない。本系は脳の信号を読まず、温度を測らず、未検証の式を証明として用いない。

## 1. 序論

### 1.1 出発点: BadaGPT電信 第 1 版

第 1 版 (論文 [26]) は次を備える。(a) 依頼文を節に分けてすべての節を仕様要素 (モジュール・対象データ・項目・機能・見た目・対象プラットフォーム・題名・目的) へ対応付け、網羅率と未解釈の節を明記する全体把握。(b) 14 種の実行時部品からの自己完結アプリ生成と機械的検証。(c) Python / Node / Bada のソースコード化と、GitHub Actions への 1 コミットによる exe / apk の自動コンパイル。(d) 生成過程の論文化 (PDF)。(e) 声も絵も文字も使わない思考入力: サイレント・トーク (非言語アトム → 固定重みのトランスフォーマー → latent)、描いた動き、本人の脈波・呼吸、脳波 BCI (集中度 / SSVEP)、Ω-Telephacy (無音の口形 viseme 認識)、画像、ChatGPT 風の対話面。(f) 位相核: 文献 17 本から取り込んだ、計算で確かめられる数理 (エントロピー位相融合・大域的部分積分・零点計数・素数ゲームの位相因子) と標識表。

第 1 版は 1 回の依頼から 1 つの成果物を作る系であり、対話はまだ「依頼文を 1 回渡す」入口にすぎない。ChatGPT のような系との最大の差は、**続けて話すほど仕様が研ぎ澄まされる**こと、**過去の発話を忘れない**こと、そして**系が自分の出力を検証し修正する**ことにある。

### 1.2 「第 23 版」の意味

本稿で「版 (version)」は製品の番号ではなく、次の三つ組で定義する能力段階である。

> **定義 1 (版).** 版 k は三つ組 V_k = (C_k, B_k, ∂_k) である。C_k はその版で加わる能力、B_k はその能力の検証電池 (機械的に実行でき、合否が決まる試験の集合)、∂_k は境界 (その版が行わないこと・主張しないこと) である。版 k の**証明書**とは、B_1, …, B_k のすべてに合格した公開ビルドである。

したがって「第 23 版」とは、本稿が定める 22 段階の能力 C_2, …, C_23 をすべて備え、その検証電池 B_1, …, B_23 のすべてに合格した BadaGPT電信のビルドを指す。これは本系の内部の尺度であり、他社の製品の版番号 (ChatGPT の何らかの「version 23」) と同じ能力であることを主張しない。利用者の要望「ChatGPT の version 23 まで進化を遂げる」を、本稿は**検証できる 22 段の梯子**として読み替えた。

### 1.3 貢献

1. 版の定義 (定義 1) と、すべての版に課す三つの不変条件 (第 2.5 節) を与え、不変条件が版の演算 (能力の追加・電池の追加) で保たれることを示す (命題 1〜3)。
2. 五つの時代に分けた第 2〜23 版の梯子を、理論・工学・検証電池・境界の四つの欄で具体化する (第 3 章、表 1)。
3. 第 2 版「会話台帳と仕様の研ぎ澄まし」を実装し (`src/ledger.js`、195 行)、16 対話の多ターン評価で基準法を上回ること、台帳の不変条件が単体テストで成り立つことを示す (第 4 章)。
4. 各時代でアーキテクチャの何が変わり何が変わらないかを工学的に整理し (第 5 章)、特に**仕様の契約は固定し、生産者を入れ替える**という設計原理を述べる。

## 2. 理論的基盤

本章は山口フレームワークの文献 ([9]〜[25]) から、計算で確かめられる部分だけを取り出して進化の基盤にする。文献自身が「偽」「未検証」「予想」と標識した式は基盤に含めない。

### 2.1 未知事前エンジン

文献 [22] (The Unknown-Prior Engine) は Bada の `cognitive_system` を次のように定式化する。(定義 1) `TupleSpace` は追記のみの不変な台帳であり、事実は蓄積されるだけで上書きされない。(定義 2) `asperal` は漸進的型付けである。(定義 3) `@reviser` は例外処理のもとで系の任意の部品を書き換えて再読み込みする反射層である。(定義 4) **未知事前**: 系の信念は、証拠のない状態では最大エントロピー (一様 / Boltzmann) の事前分布から始まり、台帳に事実が加わるにつれて尖る。文献 [21] (Full Source) はこれを実行できる Python として与え、「確信した零は正確に保存され、事後の絶対値は基底分布と機械精度で一致する (最大差 5.6×10⁻¹⁷)」ことを出力で確かめている。

本稿はこの四つを対話生成系の骨格にする。会話は台帳、いまの仕様は台帳の投影、学習は @reviser による生産者の書き換え、そして信念は未知事前から尖る。

### 2.2 零の保存とエントロピー位相融合

文献 [11] (An Entropy–Phase Mechanism for Generative AI) の原理 1 は初等的である: 非零因子の乗算だけが零点を保存し、加算・減算・積分・微分は零点を動かすか消す。その最も純粋な実現が単位絶対値の位相因子 e^{iβH} である。文献 [11] 定義 1・文献 [22] 定義 5 は、基底分布 a と補助モジュール m (分布 q^(m)、エントロピー H_m、位相 φ^(m) ∈ [−π, π]) を

> ψ_i = √a_i · exp(i Σ_m β_m H_m φ_{m,i}),  q̂_i = |ψ_i|² / Σ_j |ψ_j|²

で結合する。命題 1: (i) a_i = 0 ならどのモジュールの設定でも q̂_i = 0 (零の保存)。(ii) モジュールが一様な位相しか与えない領域では、その寄与は正規化で消える (語るのは情報のあるときだけ)。第 1 版の位相核はこれを実装し、補助チャネル (体のサイン・画像) が主チャネルの分布を変えられないことを機械精度で確かめた。

### 2.3 大域的部分積分とエントロピー項

文献 [10] (微分・積分の計算体系に関する定理の構成) の定理 6・系 2 は、生成関数 f = log x (ポテンシャル L = x log x − x のルジャンドル双対、定理 7) のもとで ∫₁ˣ log t dt + ∫₁ˣ t d(log t) = x log x を与える。x log x は文献 [15] が「エントロピーの唯一の構成要素」と呼ぶ項であり、本系では熱エネルギー経路の分解として可視化に用いる。文献 [9] 定理 I-10 の N(T) = x log x − x + 7/8 + S(T) (x = T/2π) は古典 (Riemann–von Mangoldt) であり、文献集はこれだけが「ζ は x log x である」の内容を持つ読みだと述べる。

### 2.4 標識の規律

文献 [9][16][18][19] は各式に標識を付ける: **証明済** (証明がある)、**検証済** (数値で確かめた)、**古典** (既知の定理)、**未検証** (定式化が未完)、**予想** (未解決)。文献 [11][22] は「ζ(s) = x log x」「x^{1/2+iy} = e^{x log x}」が恒等式として偽であることを明記する。本系の出力に含まれる数理は、この標識を伴わなければならない。

### 2.5 三つの不変条件

> **定義 2 (零の保存の不変条件).** 系のどの版でも、主たる情報源 (利用者が明示した依頼) が作る分布 a に対し、補助的な情報源 (センサ・画像・推定) は位相でしか作用できず、a_i = 0 の要素を復活させない。
>
> **定義 3 (追記のみの不変条件).** 系が持つ会話・仕様・学習・同意の記録は追記のみの台帳であり、除外・取り消し・やり直しも事実として追記される。投影は台帳から再計算され、台帳の事実を消さない。
>
> **定義 4 (標識付き主張の不変条件).** 系の出力に含まれる数理の主張は標識を伴い、「証明済」「古典・検証済」以外の式は可視化と重み付けにのみ用い、生成の正しさの根拠にしない。

> **命題 1 (不変条件は版の演算で保たれる).** 版の演算は (a) 能力 C の追加、(b) 電池 B の追加、(c) 生産者 (仕様を作る部品) の置換 の三種とする。これらは定義 2〜4 を保つ。
>
> *証明の骨子.* (a) 能力の追加は新しい情報源を加えるが、定義 2 により補助的な情報源は位相でしか結合されず、乗算は零を保存する (文献 [11] 原理 1)。(b) 電池の追加は記録を増やすだけで、追記のみの台帳に新しい種類の事実を足す操作である。(c) 生産者の置換は、仕様という契約 (第 5.2 節) を満たす限り、台帳の投影の形と標識の付与を変えない。いずれも定義 2〜4 の否定を含まない。∎

> **命題 2 (単調性).** 版 k の証明書は B_1, …, B_k すべての合格を要するから、版 k+1 は版 k の能力を失わない (以前の電池に不合格なら証明書が出ない)。∎

> **命題 3 (未知事前の尖り).** 台帳に支持する証拠だけが追加されるとき、モジュールへの信念のエントロピーは単調非増加である。支持する証拠とは、ある要素の重みを増やし他を変えない追記、または要素を零にする除外である。
>
> *証明の骨子.* 床 ε を持つ重み p_i ∝ ε + e_i に対し、1 要素の e_i を増やすことは最大要素への集中を進めて H を下げるか、小さい要素を増やして一時的に H を上げ得る。したがって一般の追記では単調でなく、支持する証拠に限ったとき (第 4.4 節の測定ではすべての対話で低下) に主張できる。除外は p_i = 0 とするので H は下がる。∎

命題 3 の但し書きは正直な範囲である: 新しいモジュールを足す発話は信念を広げ、エントロピーを一時的に上げ得る。本系はこれを隠さず、投影ごとのエントロピー列を表示する。

## 3. 進化の原理と版の梯子

### 3.1 五つの時代

22 段の版を五つの時代に分ける。各時代は「系が何と会話するか」で区切られる。

- **第 I 期 対話 (第 2〜5 版)** — 利用者と。続けて話すほど仕様が研ぎ澄まされ、系は自分の判断を説明し、道具を使い、前の会話を覚える。
- **第 II 期 学習 (第 6〜10 版)** — データと。規則の辞書を学習した生産者に置き換え、位相で結合するトランスフォーマー、端末内の言語モデル、根拠付けと自己評価を得る。
- **第 III 期 自律 (第 11〜15 版)** — 自分の仕事と。計画し、テストを生み、ビルドの失敗から復旧し、役割を分けた多エージェントで協調し、同意と安全を台帳で守る。
- **第 IV 期 身体 (第 16〜19 版)** — 世界と。視覚・音声・利用者ごとに学ぶ BCI・機器との接続。
- **第 V 期 自己記述 (第 20〜23 版)** — 自分自身と。Bada で自分を書き、自分を改訂し、理論の標識を機械的に守り、1 コマンドで全電池を再現する。

### 3.3 時代ごとの要点

**第 I 期 対話.** 鍵は第 2 版の台帳である。第 3 版の自己修正は、検証不合格という事実に対して候補を生成し直す @reviser であり、第 4 版の道具は対話から既存の ⑤⑥⑦ を呼ぶだけで新しい能力を要求しない。第 5 版は台帳のアーカイブ (第 2 版で既に保管している) を横断する。四つの版はいずれも**規則ベースのまま**実現でき、学習を要しない。

**第 II 期 学習.** 第 6 版で初めて生産者を学習に置き換える。ここで守るのは仕様の契約 (第 5.2 節) と未見集合の原則 (第 1 版で F1 が 100% から 81.5% へ下がった経験) である。第 7 版は文献 [11] の設計規則を実際のトランスフォーマーに入れ、第 8 版で端末内の言語モデルに至る。第 9・10 版は出力の根拠と自己評価であり、定義 4 を機械的に支える。

**第 III 期 自律.** 系が自分の仕事を計画し (第 11 版)、テストを生み (第 12 版)、ビルドの失敗から復旧し (第 13 版)、役割を分けて協調する (第 14 版)。第 15 版はセンサの同意を台帳に置く。第 1 版が「他人の計測は行わない」を文書で約束しているのに対し、第 15 版はそれを事実の有無で機械的に強制する。

**第 IV 期 身体.** 入力を広げるが、第 1 版の正直な範囲を広げない。視覚は内容を読むが顔は識別せず (第 16 版)、音声は加えるが無音の口形は残し (第 17 版)、BCI は本人の較正で精度を上げるが思考の内容は読まない (第 18 版)。

**第 V 期 自己記述.** Bada 自己ホスト (第 20 版) は文献 [24][25] の到達点 (C 参照実装 → Bada で書いたフロントエンド → Bada で書いたエンジン) を本系に適用する。第 21 版の自己改訂は、人の承認を事実として要求することで、系が自分を変える速度を人の速度に縛る。第 22 版は標識表を実行可能にし、第 23 版は全体を 1 コマンドで再現する。

## 4. 第 2 版の実装: 会話台帳と仕様の研ぎ澄まし

### 4.1 設計

台帳 `Ledger` は凍結された事実の配列である。`append` は事実に番号 t と時刻を付けて凍結し (`Object.freeze`)、以後変えられない。`read(述語)` は読み出し、`horizon` は最後の「やり直し」の次の番号 (投影の地平) を返す。事実は 6 種:

| 種 | 内容 | 誰が積むか |
|---|---|---|
| `say` | 発話 (入力元: 文字・口形・脳波・動き・画像)、原文 | 対話面 |
| `spec` | その発話から読み取った仕様の差分 (モジュール・対象・項目・機能・見た目・対象プラットフォーム・題名・目的・節・未解釈)、読み取りの旗 (汎用の退路か、項目は仮定か、対象プラットフォームは仮定か、題名は明示か、見た目に触れたか) | `ledgerSay` |
| `exclude` | 除外 (モジュール / 機能 / 対象プラットフォーム)、根拠の語 | `ledgerSay` |
| `field` | 項目の追加・除外 | `ledgerSay` |
| `forge` | 錬成の結果 (題名・モジュール・網羅率・検証) | 対話面 |
| `reset` | やり直し (地平を進める) | 対話面 |

投影 `projectSpec` は地平以後の事実を順に畳み込み、第 1 版の `comprehend` と同じ形の仕様を返す。畳み込みの規則は「ある要素についての**最後の事実が勝つ**」である。モジュール・機能・対象プラットフォームは追加と除外の最後の状態を取り、項目は明示の列挙が最後に勝ち、見た目と色は触れた発話のうち最後が勝ち、題名は明示 (「〜」という) の最後が勝ち、目的は最初の発話のものを保つ。全発話の節は投影の節に入り、網羅率は全体で計算する。除外された要素は投影の `ledger.excluded` に列挙され、台帳の事実としても残る。

モジュールへの信念は未知事前 (一様、log₂ 14 = 3.81 bit) から始まり、各 `spec` 事実で支持されたモジュールの重みを増やし、`exclude` 事実で重みを 0 (確信した零) にする。投影は事実ごとのエントロピー列を返し、対話面がそれを表示する。

### 4.2 発話の読み取り

発話は節に分け、節ごとに (a) 項目の除外 (「会社の項目は外して」)、(b) 項目の追加 (「メールも項目に足して」)、(c) 要素の除外 (除外の動詞 + 辞書の語: 「タイマーは外して」「グラフはいらない」「Linux はなしで」) を先に検出し、残りの節だけを `comprehend` に通す。これにより「タイマーは外して」の「タイマー」が追加として誤読されることを防ぐ。補足の発話 (「検索も足して」) はモジュールを含まないので `comprehend` は汎用の退路 (メモ + ToDo) を返すが、読み取りの旗がそれを示すので投影はこれを混ぜない (退路は、台帳全体に明示のモジュールが 1 つもないときにだけ使う)。

### 4.3 対話面への統合

対話面は発話を `chatRoute` で振り分ける。台帳に発話があるとき、仕様に触れる発話 (辞書の語を含む、または追加・除外の動詞を含む) は「研ぎ澄まし」として扱い、台帳に積み、投影し、第 1 版のパイプライン (電信 → 全体把握 → 生成 → 検証 → 論文) を投影した仕様で走らせ、返答に差分 (+検索 −タイマー) といまの仕様・除外・事実の数を含める。「やり直し」は `reset` 事実を積む。台帳は端末内 (localStorage) に保存され、再読み込み後も保たれる。「新しい会話」は現在の台帳を保管 (5 件まで) してから空の台帳を始める。無音の口形・脳波・動き・画像からの依頼も同じ入口を通るので、口形で「記録・管理」と発音したあとに文字で「検索も足して」と続けられる。

## 5. 工学: 各時代のアーキテクチャ

### 5.1 データの流れ

第 1 版の流れは「思考入力 → 電信 → 全体把握 → 生成 → 検証 → 論文 → ビルド一式 → Actions」である。第 2 版はその前段に台帳と投影を置く: 「発話 → 台帳 (追記) → 投影 → 全体把握と同じ形の仕様 → (以下同じ)」。第 6 版以降は「全体把握」の生産者が学習した分類器に、第 8 版で「文章生成」の生産者が言語モデルに、第 14 版で台帳が複数の役割の共有空間に、第 20 版でパイプライン全体の実装が Bada に置き換わる。流れの形は変わらない。

### 5.2 仕様の契約は固定し、生産者を入れ替える

本系で最も長く生きる設計は、仕様 (spec) の形である: 題名・目的・モジュール (id・表示名・理由)・対象データ・項目 (名・型)・機能 (id・理由・仮定か)・見た目・対象プラットフォーム・節と対応付け・網羅率・仮定・未解釈。第 2 版の投影がこの形を正確に再現したことで、生成・検証・論文・ソース化・自動コンパイルの消費者は一切変更なしに台帳の上で動いた。第 6 版 (学習する全体把握) と第 7・8 版 (トランスフォーマー・言語モデル) も同じ契約を満たす生産者として入る。これにより、各版の検証電池の多くは「消費者が同じ仕様で同じ結果を出す」という回帰試験になり、単調性 (命題 2) が機械的に確かめられる。

### 5.3 計算資源と配布

第 I 期までは規則ベースで、現在の自己完結 HTML (324 KB) のまま Android / Windows / Linux に配布できる。第 II 期は端末内の学習済み重みを要する: 第 6 版の分類器は 1 MB 未満、第 7 版のトランスフォーマーは 10⁶ パラメータ級、第 8 版の言語モデルは 10⁷〜10⁸ パラメータ級 (WebGPU / WASM、量子化) を見込む (いずれも設計上の見積もりであり、測定値ではない)。配布は現在の GitHub Actions (APK・EXE・AppImage・deb・web・論文・文献) を続け、重みは Release の資産として同梱する。第 III 期以降は Actions との往復 (第 13 版) が系の一部になる。

### 5.4 安全・同意・私秘

台帳は端末内に置き、外部へ送らない (第 5 版の電池はこれを静的に検査する)。センサは本人のものだけを扱い (第 15 版で同意の事実を必須にする)、他者の計測の要求を拒む。クラウドの言語モデル (Claude) は任意であり、既定は端末内の生産者である。これらは第 1 版の「正直な範囲」を、版が進むほど**機械的に**守る方向に強める。

### 5.5 評価の原理

(1) 未見集合: 規則や重みを育てた集合と、測る集合を分ける。(2) 単調性: 新しい版は以前の全電池に合格する。(3) 正直な標識: 出力の数理に標識を付け、電池が標識の不整合を検出する。(4) 基準法との比較: 新しい能力は、それを持たない基準法と同じ試験で比べる (第 2 版では連結法)。

## 6. 限界と正直な範囲

- **「第 23 版」は内部の尺度である.** 本稿の版は定義 1 の能力段階であり、ChatGPT を含む他社製品の版番号との対応や同等性を主張しない。
- **第 3 版以降は設計である.** 表 1 の第 3〜23 版は理論・工学・電池・境界を与えたが、実装も測定もしていない。見積もり (パラメータ数・合格条件の閾値) は設計上の目標値である。
- **第 2 版の限界.** 除外はモジュール粒度 (表 2 の #16)。読み取りは規則ベースであり、辞書にない言い回し (「音はいらない」など辞書の語を含まない除外) は未解釈として残る。評価は 16 対話であり、作者が期待を付けた。
- **命題 3 の但し書き.** 未知事前のエントロピーは支持する証拠に限って単調であり、新しいモジュールを足す発話では上がり得る。
