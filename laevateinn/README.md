# ⚔ Laevateinn v2.0 — 自動走行の自動車アシスタントAI「アル」

> **v2.0**: 🌡 赤外線カメラ × 温度計の熱画像から**ガンマ関数の大域的部分積分多様体エントロピー Ξ** を求める熱画像知覚 (無音の対象も映像化) と、🤫 声を出さず口の形で指示する**サイレントトーク操縦**を追加しました。

**レーヴァテイン**は自動走行の自動車、**アル (Al)** はそのアシスタントAIです。
これまでの集大成スタック(BadaGPT 系の意図エンジン・self-attention トランスフォーマー・
zone:// 系 AEAD 暗号)を車載システムとして一つにまとめ、依存ゼロの
**単一 HTML** (`index.html`) に収めました。

## システム構成

| サブシステム | 内容 |
|:---|:---|
| **アル (Al)** | BadaGPT 系の意図エンジンによるアシスタント。走行実況(障害物・停止・再発進・到着・タイル受信)+ 会話(「状態」「地図」「停止」「発進」「衛星」「ウェブ」)。会話から走行・モードを実際に制御 |
| **トランスフォーマー知覚** | 16 本のレイセンサをトークン化し、16 次元 QK 内積 + 近接バイアス → softmax の **attention** で脅威に注意を集中。`threat = Σ wᵢ·closenessᵢ`。前方に注意が集中すると自動減速→停止、クリアで再発進。attention はバーで可視化 |
| **🌐 Web地図モード(衛星不使用)** | 地図は**ウェブサイトから受信するタイル**(9 枚)。各タイルは zone:// 系 LCG キーストリーム AEAD の封筒で届き、**タグ検証に通ったものだけ描画**(改ざんタイルは拒否)。測位は**推測航法**(オドメトリ積分・ドリフトあり)+**ランドマーク交差点で地図座標に吸着** |
| **🛰 人工衛星モード** | 4 機の衛星 (LVT-1〜4) の擬似距離から**ガウス・ニュートン最小二乗**でトリラテレーション測位。地図タイルも衛星ブロードキャストとして受信 |
| **🕹 トランスフォーマー操縦** | トランスフォーマーの**制御ヘッド**が知覚 attention を **操舵角 (steer) と加減速 (throttle)** の 2 値に写し、その 2 値だけで車体(自転車近似モデル)を動かします。目標方位を追従しつつ、注意 × 近接度の高い側から逃げるよう転舵し、前方脅威で自動制動。操舵/加減速の出力は画面にリアルタイム表示 |
| **経路計画** | 道路網 (12×9) 上の **A\***。地図をクリックで目的地設定 → トランスフォーマーが操縦して走行 |
| **🔗 実車接続 (Bluetooth)** | **本物の Bluetooth 接続**。ELM327 互換の BLE OBD-II アダプタ (Vgate iCar Pro BLE / Veepeak BLE 等) に接続し、実車の**速度・回転数・水温・バッテリー電圧**をリアルタイム受信 (ブラウザ = Web Bluetooth / APK = cordova-plugin-ble-central)。ELM327 初期化列 (ATZ→ATE0→ATL0→ATS0→ATSP0) と PID ポーリング (010D/010C/0105/ATRV)、BLE 分割パケットの再結合、プロンプト同期のコマンドキューを実装。ハードなしでも**デモ接続**で全経路を確認可能 |
| **🔊 カーナビ連携 (音声)** | アルの案内を **Web Speech 合成 (ja-JP)** で発話。スマホがカーナビと Bluetooth オーディオでペアリング済みなら、**そのまま車のスピーカーからアルの声が流れます**(TTS 非対応 WebView では通知音にフォールバック)。速度超過やバッテリー電圧低下は自動で音声警告 |

## v2.0 — 熱画像知覚 × サイレントトーク操縦

| サブシステム | 内容 |
|:---|:---|
| **🌡 熱画像知覚 (赤外線カメラ × 温度計)** | 赤外線カメラの white-hot 熱画像を、**温度計を基準**に温度へ換算 (`T = T_amb + (Y − Y_median)/255 · span`)。温度計は **車の外気温センサ (OBD-II PID 0146、BLE で受信)**・**BLE 温度計 (Environmental Sensing 0x181A / 0x2A6E)**・手入力の3通り。熱放射は音を出さない対象 (静かに立つ歩行者・停車中の車) も写すので、**周囲が無音でも映像化**できます |
| **Γ 多様体エントロピー Ξ** | 前方 90° を方位セクタ (= 16 レイのうち前方 4 本) に分け、各セクタの温度ヒストグラムを測度として `bada_ruby` の `Manifold.invariant` と同じ式で計算: シャノン `H`、大域的部分積分 `M = Σ pᵢ · 1/(x log x)²` (x = 順位+2)、`Ξ = B(H+1, M+1) / log(N+1)`、`B(p,q) = Γ(p)Γ(q)/Γ(p+q)` (Γ は Lanczos 近似)。シーン全体の `H` から**慎重度**を出して巡航速度を最大 35% 抑えます |
| **熱源 → 16 レイ融合** | 地平線より下で外気温 +4°C 以上の画素を熱源とし、最下端の行から距離 (地面平面仮定)、最高温度から種別 (28〜42°C = 人 / 45°C 以上 = 車のエンジン・排気) を判定。レイセンサより近ければそのレイを置き換えてトランスフォーマーへ入力 → **熱画像にしか写らない歩行者でも制動**します |
| **🤫 サイレントトーク操縦** | 前面カメラで口元 (黄色い枠) を撮り、**声を出さずに口を動かす**だけで指示。`bada_silent_vim/silenttalk` の口形特徴 (開口 aperture / 横幅 spread) → 口形素 A I U O E / C(休止) を JS に移植し、3 フレーム安定で確定・休止で単語区切り。日本語の母音がそのまま口形になります: **発進=AI / 停止=EI / 左=IAI / 右へ=IE / 減速=EOU / 加速=AOU / 戻る=OU / 状態=OUAI**。カメラなしでも口形パッドと辞書チップで同じ経路を試せます |
| **安全ゲート** | 「停止」は即時。「発進」「戻る」「加速」は **5 秒以内にもう一度同じ口形**で確定。辞書にない口形は無視。サイレントトークは**目的・意図**だけを伝え、ハンドルとブレーキは常にトランスフォーマー制御ヘッドが握るので、障害物があれば指示より制動が優先されます |

### タブレットでの使い方

1. **(実車データ・温度計)** OBD-II ポートに ELM327 互換 BLE アダプタを挿し、「OBD-II に接続 (BLE)」→ 外気温 (PID 0146) が熱画像の基準温度に自動で入ります。BLE 温度計があれば「🌡 BLE温度計」でも可
2. **(赤外線カメラ)** 外付け UVC 赤外線カメラ (white-hot 出力) を USB-C で接続 →「赤外線カメラ接続」→ カメラ選択で赤外線カメラを選ぶ。ハードがなければ「デモ熱画像」
3. **(サイレントトーク)** 「前面カメラで開始」→ 口を枠に合わせ、声を出さずに「はっしん」と口を動かして口を閉じ一拍 → もう一度「はっしん」で確定。「みぎへ」「ひだり」で次の交差点を曲がる経路に組み替え、「ていし」で即停止
4. アルの音声案内は、カーナビと BT オーディオ接続済みの端末なら車のスピーカーから流れます

### 正直な範囲

- **思考そのものは読み取れません。** タブレットには脳活動を測るセンサがないため、「silent talk」は**無発声の口の動き (サイレントスピーチ)** を思考の出力として使う方式です。口形の判定は照明・顔の位置に影響される簡易な画像処理で、少数の単語の辞書に限定しています
- **タブレット内蔵カメラは熱を写せません。** 熱画像には外付けの UVC 赤外線カメラが必要です (ブラウザ / WebView から通常のカメラとして見える機種)。ironbow など疑似カラー出力の機種は white-hot に切り替えてください
- **自動走行で動くのはアプリ内のシミュレーション車両です。** 車の Bluetooth (OBD-II) から読むのは速度・回転数・水温・電圧・外気温のデータだけで、実車のハンドル・アクセル・ブレーキには一切コマンドを送りません (下の注記を参照)

## 実車での使い方 (実稼働)

1. 車の OBD-II ポート (運転席足元が多い) に **ELM327 互換 BLE アダプタ**を挿す
2. スマホをカーナビと通常どおり Bluetooth オーディオ接続しておく(アルの声が車のスピーカーに乗ります)
3. APK 版 Laevateinn を起動 → **「OBD-II に接続 (BLE)」** → アダプタを自動検出して接続
4. 実速度・回転数・水温・電圧がパネルに流れ、**🔊 音声案内** を ON にするとアルが読み上げます
5. アダプタがない場合は **「デモ接続」** で同じ経路(ELM327 初期化 → PID ポーリング → 解析)を確認できます

> 対象はデータの**読取のみ** (OBD-II Mode 01)。アクセル・ブレーキ・ハンドル等、車両の操縦系には一切コマンドを送りません。

## 使い方

1. 起動するとアルが挨拶し、地図タイルの受信が始まります(受信・検証済みの区画から地図が見えてきます)
2. 道路セルをクリック → A* が経路を計画
3. **▶ 自動走行 開始** — 障害物(車・歩行者)が現れると、アルのトランスフォーマーが前方に注意を集中して減速・停止し、クリアになると再発進します
4. 上部の **🌐 Web地図 / 🛰 人工衛星** で測位モードを切替(アルに「衛星」「ウェブ」と話しても切替可)

---

⚠️ **操縦とは何を指すか(安全のための重要な注記)**
- **トランスフォーマーが操縦するのは、アプリ内のシミュレーション車両です。** 制御ヘッドの操舵/加減速出力が画面の車を実際に動かします — これは検証可能な本物の制御ループです
- **実車(本物の自動車)のハンドル・アクセル・ブレーキは操作しません。** 市販の OBD-II (ELM327) は診断データの読取専用で、そこから操縦はできません。車両の CAN バスへ制御を注入する行為は人命に関わり、公道では違法にもなり得ます。本アプリはそれを行いません
- **実車で本物なのは**: BLE OBD-II アダプタへの Bluetooth 接続と実車テレメトリ受信 (ELM327/Mode 01)、およびカーナビの BT オーディオ経由で流れるアルの音声案内です
- 運転の主体は常にドライバーです。走行中の画面注視は避け、各地域の法令に従ってください
